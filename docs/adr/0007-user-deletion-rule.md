# ADR-0007: Правило удаления пользователя для новых таблиц

Веха v3.0 добавляет таблицы со ссылкой на пользователя: открытые ответы, фото к ответам, проверки, уведомления. Внешний ключ на `users` без правила `ON DELETE` делает удаление ученика невозможным (ошибка 23503). `ON DELETE cascade` на авторстве стирает записи, которые принадлежат другим людям, например проверки учителя.

## Решение

- **Данные ученика уходят вместе с ним.** Попытки, открытые ответы, фото, проверки его ответов и его уведомления имеют `ON DELETE cascade`: у ключа на `users` или у ключа на строку, которая сама удаляется каскадом от пользователя.
- **Файлы хранилища удаляет сервис до строк.** Если в цепочке есть файлы (фото ответа), сначала удаляются файлы в хранилище, затем строки.
- **Авторство записей для других сохраняется.** Проверяющий, автор теста, назначивший, приглашавший: `ON DELETE SET NULL`, столбец допускает NULL. Интерфейс показывает пустое авторство как «проверяющий удалён».
- **История сохраняется отключением, не удалением.** Пользователя, чьи данные нужны, отключают (`is_active = false`). Удаление необратимо: удалённые ответы и фото восстанавливаются только из резервной копии.
- **`users.created_by`** (кто пригласил пользователя) тоже авторство: `ON DELETE SET NULL`. Ключ `users_created_by_fk` переводит на это правило миграция 0026; после неё исключений в тесте-каталоге нет.

## Проверка

`app/server/src/db/user-deletion-rule.test.ts` строит список внешних ключей на `users` запросом к `pg_constraint` после всех миграций, а не списком таблиц. Каждый такой ключ имеет `confdeltype` `c` (cascade) или `n` (set null); столбец с `n` допускает NULL; внешние ключи на `test_attempts` и `test_sessions` тоже `c` или `n`. Явный список `LEGACY_EXCEPTIONS` называет ключи, которые правилу пока не соответствуют; запись, ставшая соответствовать, тест требует убрать. Поведенческий случай проверяет удаление ученика и удаление автора.

## Последствия

- Каждая миграция вехи держит тест-каталог зелёным и находит новые ключи на `users` без правки списка таблиц.
- Миграции фазы 9 занимают номера с 0026; миграции следующих фаз берут номер после них.
- Строка маршрутизации в `AGENTS.md` и раздел «Удаление пользователя» навыка `bio-exam-data` ведут к этому ADR.
