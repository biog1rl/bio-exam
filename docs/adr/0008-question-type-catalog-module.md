# ADR-0008: Каталог типов вопросов — один модуль, переопределение в тесте частичное, правило оценивания одно

## Состояние

- Правила каталога записаны в обработчиках `routes/tests/admin/question-types.ts`: системный тип не меняет шаблон, открытый тип создаёт только система, у открытого типа фиксированное правило, метрика ошибок подходит шаблону. Совместимость метрики и шаблона проверяет `routes/tests/admin/shared.ts` с ответом 400, а резолвер `lib/tests/question-type-resolver.ts` при чтении подставляет правило по умолчанию.
- Переопределение типа в тесте (`test_question_type_overrides`) пишется PUT, который заменяет строку целиком и не удаляет пустую. Web восстанавливает строку в четырёх местах (`testOverrideSteps`, `saveForTest`, `resetForTest`, `savedOverride`). Правка формулы на странице баллов перезаписывает название и отключение, загруженные страницей типа раньше.
- `questions.points` — кеш баллов вопроса. Его читают оценка (запасной максимум), экран ученика, карточка попытки у учителя и редактор. Пересчёт вызывают шесть обработчиков после записи, вне транзакции, по одному UPDATE на вопрос; правка типа пересчитывает все тесты.
- Второе понятие правил оценивания — `TestScoringRules` в `tests.scoring_rules` и `test_scoring_settings`, маршруты `/scoring-rules/*`. Оно хранится, копируется при переносе теста и попадает в экспорт, но на баллы не влияет: оценка берёт правило из каталога типов. Вызовов `/scoring-rules/*` из web нет, импорта архивов нет.

## Решение

1. **Одно правило оценивания.** Удаляются `TestScoringRules`, маршруты `/scoring-rules/*`, поле `scoringRules` в настройках теста и поля `scoringRules` и `useGlobalScoringRules` в экспорте. Новая миграция удаляет столбец `tests.scoring_rules` и таблицу `test_scoring_settings`. Правило оценивания задают тип вопроса в каталоге и переопределение типа в тесте.
2. **Модуль «каталог типов вопросов»** (`services/question-type-catalog/`). Владеет созданием, правкой и отключением типа, инвариантами каталога, совместимостью метрики и шаблона, резолвером типа для теста, записью переопределения и пересчётом `questions.points`. Маршруты разбирают запрос и переводят исход модуля в HTTP. Право проверяет маршрут, модуль принимает `testId`.
3. **Переопределение частичное.** PATCH: отсутствующее поле не меняется, `null` очищает поле, строку без значений модуль удаляет. DELETE сбрасывает переопределение целиком. PUT удаляется. При одновременной правке одного поля выигрывает последняя запись.
4. **Пересчёт в транзакции.** Изменение каталога или переопределения и пересчёт `questions.points` идут в одной транзакции, одним UPDATE и только для затронутых тестов: правка типа — тесты с вопросами этого типа, переопределение — один тест.
5. **Несовместимое правило.** Запись отвечает 400 с ошибкой поля. Чтение подставляет правило по умолчанию для строк, записанных до проверки. Политика описана в модуле один раз.

## Рассмотренные варианты

- **В модуле только переопределение.** Отклонено: правила совместимости и пересчёт общие с правкой типа, половина инвариантов осталась бы в обработчиках.
- **PUT с заменой строки и одна функция восстановления в web.** Отклонено: знание о форме строки переезжает внутри web, а не сосредотачивается у владельца данных.
- **Отдельный адрес на каждое поле переопределения.** Отклонено: три маршрута вместо одного без выигрыша.
- **Версия строки и 409 при одновременной правке.** Отклонено: правят администратор и учителя своих тестов, одновременная правка одного поля редка.
- **Убрать кеш `questions.points` и считать баллы при чтении.** Вне этого решения: меняет шесть читателей и оценку.
- **Оставить столбцы старых правил без чтения и записи.** Отклонено: мёртвые данные снова начнут читать.
- **Экспортировать действующие правила каталога вместо удалённых полей.** Отложено: импорта архивов нет, выгрузка правил каталога — отдельная задача.
- **Доказательство права (ADR-0006, механизм 4) в интерфейсе модуля.** Отложено до принятия ADR-0006: тогда запись переопределения принимает `TestWriteProof` вместо `testId`.

## Последствия

- Web: страница типа отправляет название и отключение, страница баллов — только формулу. `testOverrideSteps`, `saveForTest`, `resetForTest` и `savedOverride` удаляются. Адрес страницы баллов собирает и разбирает один модуль по образцу `app/web/lib/tests/attempts-url.ts`.
- Тесты по ADR-0003: до правок характеризация пересчёта баллов через HTTP, затем тесты интерфейса модуля на тестовой базе (инварианты каталога, частичная запись, удаление пустой строки, область пересчёта). Маршрутные тесты доступа остаются. Тесты `testOverrideSteps` удаляются вместе с функцией. `export-routes.test.ts` и `test-support/export-reference.ts` теряют поля старых правил.
- Выпуск с миграцией выкатывается вручную (`AUTO_MIGRATIONS=0`), удалённые данные остаются в дампе перед выкаткой.
- Работа выполняется отдельной фазой после фазы 11.
