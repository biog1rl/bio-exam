# Phase 10 — UI Design Contract

> Контракт на три видимые поверхности фазы 10: колокольчик с числом непрочитанных в шапке `AppLayout` и его список в `Popover` (NOTIF-02), префикс числа в заголовке вкладки (NOTIF-05) и страница перехода `/notifications/[id]` с повторной проверкой доступа (NOTIF-02, D-12, D-13). Журнал и производитель `test.assigned` (NOTIF-01, NOTIF-06) — серверная часть; здесь из неё описано только то, что приходит в web. Фаза не вводит новых цветов, токенов, npm-пакетов и компонентов `components/ui`.
>
> Решения пользователя из `10-CONTEXT.md` (D-01…D-17) обязательны. Там, где CONTEXT оставил выбор, выбран рекомендованный вариант, согласованный с существующим интерфейсом, он помечен **[авто]**. Исходное состояние кода — ветка `dev`, коммит `9bfc67a`. Стиль, токены и правила текста наследуются из `09-UI-SPEC.md`.
>
> Что подтверждено чтением кода и влияет на контракт:
> 1. `app/layout.tsx` задаёт заголовок вкладки шаблоном Next `metadata.title` (`%s - {siteConfig.name}`); Next переписывает `<title>` при каждом переходе. Записи в `document.title` в web сейчас нет нигде. Префикс `(N) ` поэтому держит отдельный клиентский компонент, который заново ставит его после каждой смены заголовка (Поверхность 3).

> 3. Сегмент `/notifications` без страницы: по правилу навигации он попадает в `NON_PAGE_PATHS` (`app/web/lib/navigation/paths.ts`), иначе кнопка «Назад» и крошки поведут на несуществующий адрес.

## Данные для интерфейса

Имена полей — рабочие, смысл фиксирован; окончательные имена решает планировщик серверной части.

| Ответ | Поле | Тип | Смысл |
|-------|------|-----|-------|
| `GET /api/notifications/unread-count` | `count` | `number` | точное число непрочитанных (D-11); единственный источник для колокольчика и вкладки |
| `GET /api/notifications?cursor=&limit=20` | `items[]` | массив строк | по убыванию `(lastEventAt, id)` |
| | `items[].id` | `string` (uuid) | для ссылки `/notifications/<id>` |
| | `items[].kind` | `string` | вид; web по нему ничего не решает, кроме `key` строки |
| | `items[].text` | `string` | готовый русский текст строки списка (см. ниже) |
| | `items[].read` | `boolean` | `read_at IS NOT NULL` |
| | `items[].lastEventAt` | `string` (ISO) | время строки: `last_event_at`, не `created_at` (повторная причина поднимает его, D-03) |
| | `nextCursor` | `string \| null` | `null` — больше нет, «Показать ещё» не показывается |
| `GET /api/notifications/:id/open` | `href` | `string` | 200: путь внутри приложения |
| | `error: 'NO_ACCESS'` | 403 | чужое, несуществующее, неизвестный вид или доступ снят (D-12) |

Текст строки собирает сервер в таблице видов `kinds.ts` из `params` события **[авто]**: D-05 кладёт текст строки в таблицу видов, и тот же текст понадобится будущим каналам (push v5.0), у которых web нет. Web печатает `text` как есть, так же как `SearchDialog` печатает `title` и `subtitle` с сервера. Контракт текста:

| Вид | Текст | Условие |
|-----|-------|---------|
| `test.assigned` | `Вам назначен тест «{testTitle}»` | `params.testTitle` — непустая строка; название на момент события, без обрезки на сервере |
| `test.assigned` | `Вам назначен тест` | `params.testTitle` пуст или отсутствует |
| любой неизвестный вид | `Новое уведомление` | вид не найден в `kinds.ts` (D-05) |

Повторное назначение (`ref_seq > 1`) текст не меняет: строка поднимается наверх списка, становится непрочитанной, время обновляется **[авто]**. Кавычки — «ёлочки», внутри названия кавычки не заменяются.

## Поверхность 1. Колокольчик и число (NOTIF-02, D-11, D-14, D-17)

**Фокус:** у каждого вошедшего в шапке видно, есть ли непрочитанные и сколько; число одно на колокольчик и вкладку.

### Место в шапке

`AppLayout.tsx`, правая группа `ml-auto flex h-full shrink-0 items-center gap-unit-mob tab-sm:gap-unit`: `NotificationBell` ставится **перед** `SearchButton` (слева от поиска), поиск остаётся в углу **[авто]**. Шапка рендерится внутри `AuthGuard`, поэтому на `/login` и `/invite` колокольчика нет. Колокольчик есть у всех ролей (D-14); у учителя и администратора список пока пуст.

### Кнопка

```tsx
<PopoverTrigger asChild>
	<Button size="icon" variant="outline" className="relative" aria-label={bellAccessibleName(count)}>
		<Bell className="size-4" aria-hidden="true" />
		{count > 0 ? (
			<span
				aria-hidden="true"
				className="absolute -top-1 -right-1 flex h-5 min-w-5 items-center justify-center rounded-full bg-primary px-1 text-xs leading-none font-medium text-primary-foreground tabular-nums ring-2 ring-background"
			>
				{badgeLabel(count)}
			</span>
		) : null}
	</Button>
</PopoverTrigger>
```

- Вид кнопки — как у `SearchButton` (`outline`, `bg-white` из варианта — унаследовано). Обёртку `SearchButton` (`div w-full max-w-xs flex-col gap-6`) и проп `size="4"` у пиктограммы не копировать.
- Подсказки (`Tooltip`) нет: у колокольчика нет горячей клавиши, а вложение `Tooltip` и `Popover` на один триггер ничего не даёт **[авто]**.
- `ring-2 ring-background` отделяет число от рамки кнопки.

### Число

| `count` | Видно на кнопке | `badgeLabel` |
|---------|-----------------|--------------|
| 0 | числа нет | — |
| 1…9 | `1` … `9` | строка числа |
| ≥ 10 | `9+` | `9+` (D-14) |
| ещё не загружено | числа нет | — |
| ошибка запроса числа | последнее известное значение (SWR держит `data`); если его не было — числа нет. Ошибки в шапке не показываются, следующий запрос — при фокусе вкладки или через 60 с **[авто]** |

При перезапросе число не мигает и не пропадает: показывается прежнее значение до прихода нового.

### Доступное имя

`bellAccessibleName(count)`, склонение через `Intl.PluralRules('ru')` **[авто]** (D-14 задаёт форму «Уведомления, N непрочитанных»; для 1, 21, 31… нужна форма единственного числа):

| `count` | Имя |
|---------|-----|
| 0 или не загружено | `Уведомления` |
| категория `one` (1, 21, 101…) | `Уведомления, {N} непрочитанное` |
| категории `few`, `many`, `other` (2, 5, 11, 22…) | `Уведомления, {N} непрочитанных` |

В имени точное число от сервера, без ограничения «9+» (D-11 ограничивает только видимое число) **[авто]**. Число на кнопке `aria-hidden`. Живой области для числа нет: рост числа при опросе не озвучивается **[авто]**. `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` ставит `PopoverTrigger`.

### Обновление (D-17)

| Событие | Что происходит |
|---------|----------------|
| вход | ключ `notificationKeys.unreadCount(userId)` зависит от пользователя: смена пользователя не показывает чужое число; без пользователя запроса нет |
| фокус вкладки | `revalidateOnFocus` |
| раз в 60 с | `refreshInterval: 60_000`, `refreshWhenHidden: false` — в скрытой вкладке опроса нет |
| открытие поповера | перезапрос числа и загрузка списка **[авто]**, чтобы число и точки в списке совпали |
| «Прочитать все», открытие уведомления | `mutate` числа и списка |

## Поверхность 2. Список в поповере (NOTIF-02, D-15, D-17)

**Фокус:** последние события видны одним нажатием; непрочитанное отличимо без цвета; любая строка ведёт на страницу перехода.

### Контейнер

```tsx
<PopoverContent
	align="end"
	sideOffset={8}
	collisionPadding={8}
	aria-labelledby={headingId}
	onOpenAutoFocus={(event) => { event.preventDefault(); headingRef.current?.focus() }}
	className="flex max-h-[min(32rem,var(--radix-popover-content-available-height))] w-[calc(100vw-1rem)] flex-col overflow-hidden rounded-3xl p-0 mob:w-96"
>
```

| Ширина | Поповер |
|--------|---------|
| 375px (и всё ниже `mob` 500px) | `calc(100vw - 1rem)`: экран минус поля шапки `p-unit-mob` 8px с каждой стороны (D-15); `collisionPadding={8}` держит края внутри экрана |
| 768px, 1280px (с `mob`) | `w-96` (384px), правый край выровнен по колокольчику (`align="end"`) |

Высота: не больше 512px и не больше места под шапкой (`--radix-popover-content-available-height`). Шапка списка не прокручивается, прокручивается только список: `div` с `min-h-0 flex-1 overflow-y-auto overscroll-contain`. `ScrollArea` не используется: Radix-область не работает с высотой «не больше» без фиксированной высоты **[авто]**. Поповер рендерится в портал, `MainScrollArea` его не касается.

### Строка

Список — `<ul className="space-y-1 p-2">`, строка — `<li>` с `Link` на `/notifications/<id>`:

```tsx
<Link
	href={`/notifications/${encodeURIComponent(item.id)}`}
	onClick={() => setOpen(false)}
	className="flex min-h-11 items-start gap-2 rounded-2xl px-2 py-2 transition-colors hover:bg-secondary/60 focus-visible:bg-secondary/60 focus-visible:ring-2 focus-visible:ring-ring focus-visible:outline-none"
>
	<span aria-hidden="true" className="flex h-5 shrink-0 items-center">
		<span className={cn('size-2 rounded-full', item.read ? 'bg-transparent' : 'bg-primary')} />
	</span>
	<span className="min-w-0 flex-1">
		{item.read ? null : <span className="sr-only">Непрочитанное: </span>}
		<span className={cn('line-clamp-3 text-sm leading-5 break-words', item.read ? 'text-muted-foreground' : 'font-medium text-foreground')}>
			{item.text}
		</span>
		<time dateTime={item.lastEventAt} title={fullDate} className="mt-1 block text-xs text-muted-foreground">
			{formatNotificationTime(item.lastEventAt, now)}
		</time>
	</span>
</Link>
```

- Место точки есть и у прочитанной строки (`bg-transparent`): текст не прыгает, когда строка становится прочитанной. Обёртка `h-5` (20px, высота первой строки текста) с `items-center` ставит точку 8px по центру первой строки без дробных отступов.
- Длинный текст: до трёх строк (`line-clamp-3`), длинное слово переносится (`break-words`), горизонтальной прокрутки нет **[авто]**.
- Нажатие закрывает поповер и открывает страницу перехода в той же вкладке; средняя кнопка и Ctrl/⌘+клик открывают её в новой вкладке (обычная ссылка).

### Время

`formatNotificationTime(iso, now)` — чистая функция с `now` в параметрах, date-fns и локаль `ru`, часовой пояс браузера (часовой пояс пользователя вне фазы, D-05) **[авто]**:

| Разница с `now` | Текст |
|-----------------|-------|
| меньше 1 мин или время в будущем (рассинхрон часов) | `только что` |
| 1–59 мин | `{n} мин назад` |
| тот же календарный день, от 1 ч | `{n} ч назад` |
| предыдущий календарный день | `вчера в {HH:mm}` |
| 2–6 календарных дней | `{n} дн. назад` |
| раньше, тот же год | `{d MMM}` (`6 окт.`) |
| другой год | `{d MMM yyyy}` (`6 окт. 2025`) |

Полная дата в `title` и для проверки: `d MMMM yyyy, HH:mm` (`6 октября 2026, 14:05`). Время не тикает таймером: пересчитывается при каждом рендере списка (открытие, перезапрос, «Показать ещё») **[авто]**.

| Действие | Результат |
|----------|-----------|

## Поверхность 3. Заголовок вкладки (NOTIF-05, D-16)

| `count` | `document.title` |
|---------|------------------|
| 0 или не загружено | без префикса: `{страница} - {сайт}` как сейчас |
| 1…9 | `({N}) {страница} - {сайт}` |
| ≥ 10 | `(9+) {страница} - {сайт}` |

`UnreadTitlePrefix` — клиентский компонент без разметки внутри `AuthGuard` шапки (на `/login` его нет), читает тот же ключ числа, что колокольчик:
- при изменении числа и при каждой смене `<title>` (`MutationObserver` на `document.head` с `childList` и `characterData`, `subtree`) снимает существующий префикс `^\(\d+\+?\) ` и ставит новый; запись не повторяется, если заголовок уже верный — иначе наблюдатель зациклится;
- при размонтировании (выход) снимает префикс;
- префикс стоит перед всей строкой шаблона Next, а не перед названием страницы.

`titlePrefix(n)` (`''`, `'(N) '`, `'(9+) '`) и `badgeLabel(n)` делят одно правило ограничения.

## Поверхность 4. Страница перехода `/notifications/[id]` (NOTIF-02, D-12, D-13)

Файлы: `app/web/app/(internal)/(protected)/notifications/[id]/page.tsx` (`metadata.title = 'Уведомление'`, вкладка `Уведомление - {сайт}`) и клиентский компонент. В `NAV_SECTIONS` не добавляется: адрес с параметром. `/^\/notifications$/` добавляется в `NON_PAGE_PATHS` (`lib/navigation/paths.ts`): «Назад» без истории ведёт на `/dashboard`. Подпись крошки — `Уведомление` через `SetBreadcrumbsLabels`.

**Фокус:** ссылка из уведомления никогда не показывает материал без повторной проверки и ничего не рассказывает о недоступном объекте.

`open` меняет данные (отмечает прочитанным), поэтому вызывается только из клиентского эффекта после монтирования; `page.tsx` и серверный рендер его не вызывают, иначе предзагрузка (`prefetch`) ссылок `Link` в списке отмечала бы события прочитанными. Клиентский компонент вызывает `GET /api/notifications/:id/open` один раз за показ (защита от двойного вызова эффекта в строгом режиме — флаг в `ref`), затем `mutate` числа и списка в любом исходе, кроме сетевой ошибки.

| Исход `open` | Экран |
|--------------|-------|
| идёт запрос | `<section role="status" className="flex items-center gap-2 rounded-4xl border border-border/80 bg-card/90 p-unit-mob text-sm text-muted-foreground tab-sm:p-unit">` с `Loader2 size-4 animate-spin` (`aria-hidden`) и текстом `Открываем уведомление…` **[авто]** |
| 200 `{ href }` | `router.replace(href)`: адрес `/notifications/<id>` не остаётся в истории, «Назад» со страницы теста ведёт туда, откуда открыли уведомление. До смены страницы остаётся экран «идёт запрос» |
| 403 `NO_ACCESS` (сюда же чужой и несуществующий id, неизвестный вид, D-12) | `AccessDeniedState` (Copywriting): без названия, slug, причины и любых данных объекта |
| сеть, 5xx, ответ неверной формы | `LoadErrorAlert` с заголовком `Не удалось открыть уведомление`; «Повторить» вызывает `open` снова |
| 401 | цепочка `apiFetch` (refresh или `/login`), своей обработки нет |

Web не проверяет формат id: любой id уходит на сервер, неверный даёт `NO_ACCESS`. `href` берётся только с сервера; web принимает только путь, начинающийся с одного `/` (не `//` и не схему) — иначе экран как у `NO_ACCESS` **[авто]**.

Фокус: на экране «Нет доступа к материалу» фокус ставится на заголовок `h1` (`tabIndex={-1}`, без видимого кольца), как в `PageErrorState`; если у `AccessDeniedState` нет такой возможности, ему добавляется необязательный `headingRef`, вёрстка не меняется. У `LoadErrorAlert` фокус — его собственное поведение.

Ширина 375 / 768 / 1280px: карточки во всю ширину области контента, как у остальных экранов `AccessDeniedState`; кнопка «На главную» во всю ширину до `mob`, затем по содержимому (унаследовано).
