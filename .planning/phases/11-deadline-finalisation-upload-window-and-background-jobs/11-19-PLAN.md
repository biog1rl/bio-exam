Решения плана (записать в SUMMARY):
- Словарь строится на видах `FinalizeOutcome` (`finalized`, `submitted`, `expired`, `superseded`, `not_found`), которые уже закреплены тестами финализации и отчётом задачи; к ним добавлены `open` с сессией, `saved`, `accepted`, `answers_invalid`, `no_questions`. `finalized` — попытка сессии сдана сервером по дедлайну (кто бы её ни создал), `submitted` — клиентом из другого запроса (`attemptId` может быть `null`), `accepted` — попытка этого запроса (создана или повтор того же `clientAttemptId`; используется с 11-22).
- `finalized` или `submitted` решает одна функция `classifySubmitted` по столбцу `test_attempts.submit_source` (сейчас финализация сравнивает `client_attempt_id` с `deadline:<sid>`; попытки `deadline` создаёт только финализация, обе проверки совпадают на всех строках).
- `open` несёт `session: SessionInfo` (с `serverNow` из того же чтения): `/start` отдаёт её целиком, GET судьбы берёт `sessionId`, `startedAt`, `serverNow`; повторного чтения `started_at` после финализации нет.
- Имя `finalizeSessionByDeadline(sessionId, owner?)` сохраняется: его вызывают задача и GET судьбы, его называют документы 11-18. Отдельной функции чтения судьбы нет.
- Публичная команда `startAttemptSession(pair)` финализирует сама; `SessionNeedsFinalizationError` и предвызов `finalizeExpiredOpenSession` убираются; внутренняя транзакция старта переименовывается (например `openOrStartSession`). Закрепление сервиса «startAttemptSession на просроченной сессии» (ждало исключение) меняется отдельным шагом красный → зелёный на исходы команды.
- Правило ответов черновика читает все вопросы теста (как финализация сейчас), а не один вопрос: ключ черновика, не похожий на UUID, остаётся `foreign_question`, а не ошибкой запроса к базе. Неверная форма значения даёт причину `answer_shape_invalid` (раньше в логе `invalid_value`; на ответы API не влияет — у PATCH значение уже разобрано схемой).
- Цикл повторов при смене черновика вынесен в `untilDraftSettles(step, rounds)` и проверяется таблицей с подменным шагом; транзакционная часть (`draft_changed` при устаревшем `expectedDraft`) остаётся закреплённой тестом на базе.
- `serverNow` в телах 409 финализации и судьбы `submitted`/`expired` читает `sendSessionOutcome` одним вызовом `databaseNow()` после решения, как сейчас; исходы `open` и `saved` несут `serverNow` из своего чтения в базе.
- Промежуточное состояние до 11-22: `/submit` идёт прежними шагами `precheckSubmit` и `submitAttempt` (экспорт из `index.ts` и `ScoredAttemptFacts` остаются), ответ 409 этого маршрута собирает `submittedBody` по виду попытки, как сейчас.
- `commands.test.ts` по гигиене тестов: только случаи, которых нет в HTTP-наборах (attempt-deadline, attempt-submit, attempt-time-limit, attempt-races).
