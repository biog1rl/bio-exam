# Phase 11 — UI Design Contract

> Контракт на видимые поверхности фазы 11: страница попытки после дедлайна по серверному времени (TIME-02, D-12), исход «Ответ принят» с строкой окна для фото и обратным отсчётом от серверного времени (TIME-03, TIME-06, D-10, D-13), пометка о тексте, набранном без связи и не дошедшем до сервера (D-14), исход «время вышло» у пустой попытки (D-04, тексты прежние), поле «Окно для фото после окончания времени, мин» в настройках теста (D-07, D-11), текст отказа фото (D-09, для фаз 12–13). Фоновые задачи, остановка API, обновление сессии во всех вкладках и чистка ключей при выходе (PLAT-01…PLAT-04) видимого интерфейса не имеют (Поверхность 7). Фаза не вводит новых цветов, токенов, npm-пакетов и компонентов `components/ui`.
>
> Решения из `11-CONTEXT.md` (D-01…D-20; D-04 и D-07 — решения пользователя) обязательны. Там, где CONTEXT оставил выбор, выбран рекомендованный вариант, согласованный с существующим интерфейсом, он помечен **[авто]**. Исходное состояние кода — ветка `dev`, коммит `c0288a9`. Стиль, токены и правила текста наследуются из `09-UI-SPEC.md` и `10-UI-SPEC.md`.
>
> Что подтверждено чтением кода и влияет на контракт:
> 1. `Input` (`components/ui/input.tsx`) несёт `disabled:opacity-50`. Сейчас `TestRunner` передаёт `disabled={interactionDisabled}` во все поля, а `interactionDisabled` истинно в фазах `submitting`, `autoSubmitting`, `submitted`, `blocked`. Текст в выключенном поле даёт 3,18:1 (ниже AA 4,5:1). Поэтому «только для чтения» после дедлайна — это `readOnly`, а не `disabled` (Поверхность 1).
> 2. `failSubmit` (`attempt-lifecycle/lifecycle.ts`) после сбоя автосдачи возвращает модуль в `active`: поля снова редактируются уже после дедлайна. Контракт это запрещает (Поверхность 1).
> 3. Оверлей «Время вышло / Отправка ответов...» (`fixed inset-0 bg-black/50`, без роли диалога) показывается только после успешного ответа сервера на 1,5 с (`showTimeUp`, `TIME_UP_PAUSE_MS`) и закрывает весь экран. TIME-06 требует, чтобы ученик видел свой текст, поэтому оверлей заменяется панелью в потоке страницы.
> 4. Разметка `flex-col tab:flex-row`: ниже 1024px правая панель с таймером стоит **под** вопросом. На 375 и 768px главный сигнал дедлайна — панель вверху области контента, а не таймер.
> 5. `secondsLeft()` считает по часам устройства против серверного `startedAt`. По D-10 таймер и обратный отсчёт окна считаются от серверного времени.
> 6. `attempt-submit-flow.ts` стирает все ключи (`session`, `wal`, `frozen`, `clientAttemptId`) при `already-submitted` и `time-expired`. По D-14 WAL при серверной финализации стирается только после сверки (Поверхность 3).
> 7. В настройках теста соседнее поле пишет `value={form.timeLimitMinutes || ''}`: ноль показывается пустым полем. У нового поля 0 — осмысленное значение «окна нет» (D-06), копировать этот приём нельзя (Поверхность 5).

## Данные для интерфейса

Имена полей — рабочие, смысл фиксирован; окончательные имена решает планировщик серверной части. Как отдавать `serverNow` (поле или заголовок) — Discretion CONTEXT; контракт требует только, чтобы он приходил в каждом ответе из таблицы.

| Ответ | Поле | Тип | Смысл |
|-------|------|-----|-------|
| `/start`, `PATCH …/answers`, `/submit` 200, `/submit` 409, чтение сессии | `serverNow` | `string` (ISO) | время базы на момент ответа (D-10); web пересчитывает смещение часов при каждом таком ответе |
| `AttemptView` (ответ `/submit` 200 и попытка в 409 и в чтении сессии) | `uploadClosesAt` | `string \| null` (ISO) | конец окна для фото (D-08); `null` — окна нет |
| | `submitSource` | `'client' \| 'deadline'` | кто сдал попытку (`test_attempts.submit_source`) |
| `/submit` 409 `ATTEMPT_ALREADY_SUBMITTED` | `attemptId` | `string` | как сейчас |
| | `submitSource` | `'client' \| 'deadline'` | по нему web выбирает исход: `deadline` → «Ответ принят», `client` → существующий диалог «Попытка уже сдана» (D-05, D-13) **[авто]** |
| | `attempt` | `AttemptView`, необязательно | рекомендуется отдавать владельцу попытки: тогда исход показывается сразу, как после обычной сдачи, и сверка WAL идёт по `attempt.results[].userAnswer`. Без него — запасная панель (Поверхность 2) |
| Чтение сессии по `sessionId` из `localStorage` при открытии страницы | `state` | `'open' \| 'submitted' \| 'expired'` | `submitted` несёт `submitSource` и `attempt` (как в 409); `expired` — сессия закрыта без попытки (D-04) |
| Тест в редакторе (`GET` теста, `PATCH` настроек) | `photoUploadWindowMinutes` | `number`, целое 0…120 | D-06, D-07; у нового теста 15 |
| Отказ фото (D-09, маршруты фаз 12–13) | `error: 'UPLOAD_WINDOW_CLOSED'` | 409 или 422 — решает планировщик | окно закрылось; несёт `uploadClosesAt` |
| | `error: 'UPLOAD_WINDOW_NONE'` | то же | у попытки нет окна (`upload_closes_at IS NULL`) |

Часы (D-10) **[авто]**: `offset = Date.parse(serverNow) − deviceNowПриПолучении`; `now() = Date.now() + offset`. Этим `now()` пользуются три места: таймер попытки (`secondsLeft`), момент «после дедлайна» для перевода полей в чтение и обратный отсчёт окна. Абсолютное время «до ЧЧ:ММ» форматируется из `uploadClosesAt` в часовом поясе браузера и от смещения не зависит. Если ответа с `serverNow` ещё не было, `offset = 0`.

## Поверхность 1. Страница попытки после дедлайна (TIME-02, D-01, D-12)

**Фокус:** когда серверное время дошло до дедлайна, ученик видит, что время вышло и ответы уходят, может прочитать свой текст, но не может его менять.

### Момент «после дедлайна»

Дедлайн — `startedAt + timeLimitMinutes`, «сейчас» — `now()` с поправкой на серверные часы (раздел «Данные для интерфейса»). Грейс `ATTEMPT_GRACE_PERIOD_MINUTES` на интерфейс не влияет: поля переходят в чтение ровно в дедлайн, автосдача стартует там же, как сейчас (D-12). Грейс нужен серверу, чтобы принять черновик, отправленный до дедлайна и дошедший позже (D-01). У теста без лимита этого состояния нет (D-03).

Снимок модуля получает признак `deadlinePassed: boolean` **[авто]**; он истинен с дедлайна до перехода к исходу или нового старта и **не сбрасывается** при сбое автосдачи. `failSubmit` после дедлайна не возвращает модуль в редактируемое состояние: `answer()` в этом состоянии ничего не делает.

### Поля ответов

| Поле | После дедлайна |
|------|----------------|
| `Input` текстовых шаблонов (`short_text`, `sequence_digits`; в фазе 14 — текст `open`) | `readOnly` (не `disabled`), класс `read-only:bg-muted`, `placeholder` убирается (пустое поле не предлагает «Введите ответ»). Поле остаётся в порядке Tab, текст выделяется и копируется, кольцо фокуса прежнее |
| `RadioGroup`, `Checkbox`, `Select` | `disabled`, как сейчас при `interactionDisabled` (поведение не меняется, вне D-12) |
| «Назад», «Далее», номера вопросов в правой панели | доступны **[авто]** (сейчас «Назад» и «Далее» выключены в `autoSubmitting`): при сбое связи исход может прийти не сразу, и всё это время ученик может перечитать свои ответы. Переход между вопросами не меняет ответов |
| «Завершить» (обе кнопки) | `disabled`; текст `Отправка…` во время отправки, иначе `Завершить` |

`QuestionInput` получает отдельный проп `readOnly` рядом с `disabled` **[авто]**: в `active` оба ложны, после дедлайна текстовые поля получают `readOnly`, а выбор — `disabled`. До дедлайна в фазах `submitting` (ручная сдача) поведение прежнее.

### Таймер

| Состояние | Правая панель |
|-----------|---------------|
| до дедлайна | как сейчас: `mm:ss` или `hh:mm:ss`, красный с 5 минут до конца |
| с дедлайна до исхода | `00:00` (или `00:00:00`), `text-red-600`; таймер не скрывается, пока нет исхода |
| исход показан | таймер скрыт (как сейчас при `submitResult`) |

Разметка таймера: `<div role="timer">` с `<span className="sr-only">Осталось времени: </span>` перед цифрами. `role="timer"` не озвучивает изменения сам; посекундных объявлений нет.

### Панель «Время вышло» (`DeadlinePanel`)

Стоит вверху левой колонки, на месте панели результата (между шапкой теста и вопросом), на всех ширинах. Ниже 1024px это главный признак дедлайна: таймер там находится под вопросом. Прежний оверлей `fixed inset-0 bg-black/50` удаляется **[авто]**: он закрывал текст, который TIME-06 требует показывать. Флаг `showTimeUp` и пауза `TIME_UP_PAUSE_MS` закреплены `lifecycle-time.test.ts`; планировщик сохраняет паузу (панель тогда видна не меньше 1,5 с перед исходом) или убирает её вместе с правкой характеризации — видимый контракт одинаков.

| Состояние | Разметка | Текст |
|-----------|----------|-------|
| идёт отправка (`autoSubmitting`, пауза перед исходом) | `<section role="status" className="rounded-lg border border-border bg-card p-4">`; `h2 text-lg font-semibold` и строка `mt-2 flex items-center gap-2 text-sm text-muted-foreground` с `Loader2 size-4 animate-spin` (`aria-hidden`) | `Время вышло` / `Отправляем ответы…` |
| отправка не удалась (сеть, 5xx) | `<section className="rounded-lg border border-rose-200 bg-rose-50 p-4">`; `h2` тот же; текст `mt-2 text-sm` в `<p role="alert">`; кнопка `Отправить ответы` (`variant="outline" size="sm"`, `mt-2`) | `Время вышло` / текст из Copywriting «сбой отправки после дедлайна» |
| повтор идёт | как «идёт отправка» | `Время вышло` / `Отправляем ответы…` |

В состоянии сбоя существующая красная плашка `retry` («Не удалось сохранить ответы…») не показывается: панель дедлайна её заменяет, двух красных блоков нет **[авто]**. Повтор запускается кнопкой и сам при событиях `online` и `visible` **[авто]**, `clientAttemptId` прежний (повтор не создаёт вторую попытку). Если сервер к повтору уже сдал попытку сам, ответ 409 с `submitSource: 'deadline'` ведёт к исходу «Ответ принят» (Поверхность 2).

### Исходы автосдачи и что видно

| Ответ сервера | Исход |
|---------------|-------|
| 200 | панель результата с заголовком `Ответ принят` (Поверхность 2) |
| 409 `ATTEMPT_ALREADY_SUBMITTED`, `submitSource: 'deadline'` | то же, «Ответ принят» (D-05, D-13) |
| 409, `submitSource: 'client'` | существующий диалог «Попытка уже сдана» (сдано из другой вкладки) |
| 422 `TIME_EXPIRED` | существующий диалог D-04 (Поверхность 4) |
| 403, 404 | существующие плашки `submit-not-assigned`, `not-found`; панель дедлайна скрывается |
| сеть, 5xx | панель дедлайна в состоянии сбоя |

### Возврат на страницу после дедлайна

При открытии страницы с сохранённой сессией web спрашивает сервер о ней (чтение сессии, ленивая финализация D-02):

| `state` | Что видно |
|---------|-----------|
| `open` (до дедлайна плюс грейс) | как сейчас: восстановление и тост `Сессия восстановлена`; если дедлайн уже прошёл, сразу панель «Время вышло» и автосдача |
| `submitted` + `deadline` | исход «Ответ принят» без диалога «Начать тест?» (Поверхность 2) **[авто]** |
| `submitted` + `client` | сдано из другой вкладки или до перезагрузки: существующий диалог «Попытка уже сдана» с «К результатам» и «Закрыть», без «Ответ принят» и без диалога «Начать тест?» **[авто]** |
| `expired` (D-04 или D-21) | без текста в WAL этой сессии — как сейчас для заброшенной просроченной сессии: диалог «Начать тест?» с полным временем (попытки нет, в результатах ничего); с непустым текстом в WAL — тот же исход, что 422 «время вышло»: диалог «Время вышло» с пометкой о недошедшем тексте, WAL стирается только по «Начать заново» (таблица WAL ниже) |
| сеть | как сейчас (восстановление из локальной копии) |

### Фокус и объявления

- В дедлайн фокус не переносится: если ученик стоял в текстовом поле, фокус остаётся в нём (поле стало только для чтения). Объявление даёт `role="status"` панели: `Время вышло. Отправляем ответы…` — один раз.
- Сбой отправки объявляется через `role="alert"` текста сбоя.
- Когда появляется исход, фокус переходит на его заголовок (Поверхность 2).

## Поверхность 2. Исход «Ответ принят» и строка окна для фото (TIME-03, TIME-06, D-08, D-10, D-13)

**Фокус:** ученик, у которого время вышло, видит, что ответ принят, а не «ответы не засчитаны», и — если в тесте есть окно — до какого времени можно добавить фото.

### Панель результата

Та же `section` панели результата `TestRunner` (цвет по виду результата: `bg-secondary` для «на проверке», `bg-emerald-50` для итога — унаследовано). Меняется только верх:

| Исход | Заголовок `h2` | Строка под заголовком |
|-------|----------------|------------------------|
| ручная сдача (`submitSource: 'client'`, своя вкладка) | `Результат` (как сейчас) | нет |
| автосдача по таймеру или серверная финализация | `Ответ принят` | `<p className="text-sm">Время вышло, ответы приняты автоматически.</p>` |

Ученику не важно, кто сдал попытку — его вкладка по таймеру или сервер, поэтому оба пути дают один заголовок **[авто]**. Ниже — строка окна (если `uploadClosesAt !== null`), пометка D-14 (если есть), затем существующее тело результата (`AttemptReviewLine` и пояснение для «на проверке», баллы, процент и статус для итога) и кнопки `Пройти ещё раз`, `К тесту`, `Ко всем тестам`. Карточки вопросов показывают разбор, как после обычной сдачи.

Строка окна показывается при любом исходе с `uploadClosesAt`, в том числе после ручной сдачи (окно начинается с момента сдачи, D-08). Сейчас `open` выключен (фаза 17), поэтому строку видно только на засеянном открытом вопросе в dev и e2e.

Запасная панель, если 409 пришёл без `attempt` **[авто]**: заголовок `Ответ принят`, строка `Время вышло, ответы приняты автоматически.`, строка окна не показывается (нет `uploadClosesAt`), текст `Результат появится в списке «Мои попытки» после обновления страницы.` и кнопка `К результатам` (`window.location.reload()`, как в диалоге «Попытка уже сдана»). Цвет — `bg-secondary`.

Фокус: при появлении панели фокус ставится на `h2` (`tabIndex={-1}`, `outline-none`, без видимого кольца), как заголовок поповера в фазе 10. Это относится к любому исходу, включая ручную сдачу **[авто]**, и заменяет решение **[авто]** из `09-UI-SPEC.md` (Поверхность 4: «Панель появляется после сдачи без перехода фокуса»): кнопка «Завершить», на которой стоял фокус, становится неактивной, фокус уходит в `body`, а после автосдачи ученик без переноса вообще не узнаёт об исходе с клавиатуры и экранного диктора. Перенос фокуса прокручивает `MainScrollArea` к панели. Панель не помечается живой областью: озвучивание даёт перенос фокуса.

e2e: `e2e/tests/timed-attempt.spec.ts` после автосдачи ждёт заголовок `Результат`; план фазы меняет ожидание на `Ответ принят`. Проверка `getByText('Время вышло', { exact: true })` остаётся верной: так называется заголовок панели дедлайна, и он пропадает при исходе (строка `Время вышло, ответы приняты автоматически.` с ней не совпадает).

### Строка окна (`UploadWindowLine`)

`uploadWindowView(uploadClosesAt, now)` — чистая функция, `now` с поправкой на серверные часы. Порог «скоро закроется» — 5 минут **[авто]**, как красный таймер по умолчанию.

| Состояние | Условие | Видимый текст | Вид |
|-----------|---------|---------------|-----|
| окна нет | `uploadClosesAt === null` | строки нет | — |
| открыто | осталось больше 5 мин | `Фото можно добавить до {время}` и `осталось {m} мин` | первая часть `text-sm text-foreground`, отсчёт `text-sm text-muted-foreground` |
| скоро закроется | осталось от 1 до 5 мин | `Фото можно добавить до {время}` и `закроется через {m} мин` | отсчёт `font-medium text-foreground` с `Clock3 size-4` слева (`gap-1`, `aria-hidden`) |
| последняя минута | осталось меньше 60 с | `Фото можно добавить до {время}` и `закроется меньше чем через минуту` | как «скоро закроется» |
| закрыто | `now ≥ uploadClosesAt` | `Время для добавления фото закончилось в {время}` | `text-sm text-muted-foreground`, отсчёта нет |

- `{m}` — целые минуты вверх: `ceil((uploadClosesAt − now) / 60000)`.
- `{время}` — `HH:mm` (24 часа) в часовом поясе браузера; если день окончания окна не совпадает с сегодняшним днём по `now`, — `d MMM, HH:mm` (`7 окт., 00:15`) **[авто]**. Пример: `Фото можно добавить до 14:35`, `Время для добавления фото закончилось 7 окт. в 00:15` — для другого дня в «закрыто» стоит `{d MMM} в {HH:mm}`.
- Разметка: `<p className="mt-2 flex flex-wrap items-center gap-x-2 text-sm">`; ниже `mob` (500px) отсчёт уходит на вторую строку (`basis-full mob:basis-auto`, `mt-1 mob:mt-0`).
- Обновление: один таймер до следующей границы минуты, до порога 5 минут или до закрытия — что раньше; посекундного тика нет **[авто]**. При возврате во вкладку (`visible`) пересчёт сразу.

Объявления: видимая часть с отсчётом `aria-hidden="true"`, рядом `<span className="sr-only">` с полным предложением при первом показе (`Фото можно добавить до 14:35.`), и отдельная `<span className="sr-only" aria-live="polite">`, текст которой меняется **только** на переходах состояний: в «скоро закроется» — `Окно для фото закроется через 5 минут.`, в «закрыто» — `Время для добавления фото закончилось.`. Ежеминутные изменения не озвучиваются.

## Поверхность 3. Текст, набранный без связи и не дошедший до сервера (D-14)

**Фокус:** если сервер принял попытку без части текста, который ученик набрал без связи, этот текст не пропадает молча: ученик видит, что он не дошёл, и может его прочитать.

### Сверка

`wal-reconcile.ts` **[авто]**: для каждого вопроса текстового шаблона из локальной копии (WAL) сравнивается строка ответа с `attempt.results[].userAnswer` того же вопроса; сравнение — после `trim()`, пустая локальная строка не считается расхождением. Ответы выбора не сверяются (их нельзя «набрать без связи» частично; сервер принял последнее сохранённое).

| Исход | Ключи `session`, `frozen`, `clientAttemptId` | WAL |
|-------|-----------------------------------------------|-----|
| 200 своей отправки (ручной или автосдачи) | стираются, как сейчас | стирается, как сейчас: отправлены ответы этой вкладки |
| «Ответ принят» с `attempt` (409 `deadline`, чтение сессии `submitted` + `deadline`) | стираются сразу | сверка: всё совпало — стирается; есть расхождение — запись остаётся, привязанная к `attemptId`, и показывается пометка |
| «Ответ принят» без `attempt` (запасная панель) | стираются сразу | сверять не с чем: остаётся, если в ней есть неподтверждённые текстовые ответы (`pending`), и показывается пометка со словом «могла» (Copywriting) **[авто]** |
| 409 `client` (другая вкладка) | как сейчас, всё стирается | как сейчас |
| 422 `TIME_EXPIRED` (D-04, попытки нет) | стираются сразу | остаётся, пока открыт диалог; если в ней есть непустой текст, диалог показывает пометку (Поверхность 4); стирается по «Начать заново» **[авто]** |
| Чтение сессии `expired` (D-04 или D-21, попытки нет) при непустом тексте WAL этой сессии; то же при сбое чтения, когда сессия по часам брошена просроченной | стираются сразу | как у 422: вместо диалога «Начать тест?» — диалог «Время вышло» с пометкой (Поверхность 4), при сбое чтения — со словом «могла»; WAL остаётся, пока открыт диалог, стирается по «Начать заново» **[авто]** |

Сохранённая запись удаляется, когда ученик начинает этот тест заново (`Пройти ещё раз`, `Начать заново`, подтверждение «Начать тест?») и при выходе из аккаунта (D-20). После перезагрузки страницы исход попытки не восстанавливается (как сейчас), и пометка не показывается; запись удаляется при следующем старте **[авто]**.

### Пометка (`UnsentTextNote`)

Внутри панели результата, после строки окна, до тела результата:

```tsx
<div className="mt-2 rounded-lg border border-dashed border-border bg-card p-4">
	<p className="text-sm font-medium">Часть ответа, набранная без связи, не дошла до сервера</p>
	<p className="mt-1 text-sm text-muted-foreground">Засчитан ответ, который успел сохраниться. Ниже — текст с этого устройства, его нельзя изменить.</p>
	<ul className="mt-2 space-y-2">
		<li>
			<div className="flex items-center justify-between gap-2">
				<span className="text-xs font-medium">Вопрос {n}</span>
				<Button variant="ghost" size="sm" className="h-11 rounded-full tab:h-8">К вопросу {n}</Button>
			</div>
			<div tabIndex={0} aria-label={`Текст вопроса ${n} с этого устройства`} className="mt-1 max-h-40 overflow-y-auto rounded-md border border-border bg-muted px-3 py-2 text-sm leading-6 whitespace-pre-wrap break-words">
				{localText}
			</div>
		</li>
	</ul>
</div>
```

- Текст — обычный блок, не поле ввода: его нельзя изменить, он выделяется и копируется. `tabIndex={0}` нужен, чтобы длинный текст прокручивался с клавиатуры; кольцо фокуса — `focus-visible:ring-2 focus-visible:ring-ring`.
- `px-3` (12px) у блока текста — те же поля, что у `Input`, чтобы текст стоял так же, как стоял в поле; это единственное новое место с 12px; `mt-3` рядом — существующий отступ контейнера, фаза его не меняет.
- «К вопросу {n}» вызывает `lifecycle.navigate` и показывает карточку разбора этого вопроса с ответом, который засчитан, — ученик сравнивает два текста. Фокус после нажатия — на номер вопроса в карточке.
- Записи по порядку вопросов; номер — порядковый номер вопроса в тесте.
- Без копирования в буфер и без отправки текста учителю: в фазе этого нет **[авто]**.

## Поверхность 5. Поле окна в настройках теста (TIME-02, D-06, D-07, D-11)

### Место и видимость

`TestSettingsPanel`, группа `Прохождение`, сразу под полем `Лимит времени, минут` (до порогов таймера) — «рядом с лимитом времени» (D-07). Поле видно только когда `form.questions.some((q) => q.questionUiTemplate === 'open')` (D-11). Тип `open` засеян выключенным до фазы 17, поэтому сейчас авторы поле не видят; исполнитель проверяет его на засеянном открытом вопросе в dev и e2e. Когда поле скрыто, значение не меняется и уходит в API как есть (API принимает поле всегда).

### Разметка

```tsx
<div className="space-y-2">
	<Label htmlFor="test-settings-photo-window">Окно для фото после окончания времени, мин</Label>
	<Input
		id="test-settings-photo-window"
		type="number"
		inputMode="numeric"
		min={0}
		max={120}
		step={1}
		value={form.photoUploadWindowMinutes ?? ''}
		aria-invalid={photoWindowError ? true : undefined}
		aria-describedby="test-settings-photo-window-hint"
		className={photoWindowError ? 'border-destructive focus-visible:ring-destructive' : ''}
	/>
	<p id="test-settings-photo-window-hint" className={cn('text-xs', photoWindowError ? 'text-destructive' : 'text-muted-foreground')}>
		{photoWindowError ?? hint}
	</p>
</div>
```

- `value={form.photoUploadWindowMinutes ?? ''}`, **не** `|| ''`: у соседнего поля лимита `|| ''` превращает 0 в пустое поле, а здесь 0 — «окна нет».
- Значение в форме: `number | null`; пустое поле — `null` (и ошибка), иначе `Number(e.target.value)`. `parseInt` не используется: он молча превращает `12.5` в `12`.
- Новый тест — 15 (`createInitialTestForm`, D-07); существующий — значение с сервера.
- Подсказка (когда ошибки нет) зависит от лимита времени: с лимитом — `Отсчёт — от сдачи или конца таймера, что раньше. 0 — фото только до сдачи.`; без лимита — `Отсчёт — от сдачи теста. 0 — фото только до сдачи.`

### Проверка

| Ввод | Сообщение под полем |
|------|---------------------|
| пусто | `Укажите число минут от 0 до 120` |
| дробное, отрицательное, больше 120 | `Введите целое число минут от 0 до 120` |
| 0…120, целое | подсказка |

- Ошибка показывается при вводе (как у адреса теста), `text-destructive` и рамка `aria-invalid`.
- «Сохранить» при ошибке: сохранение не идёт, `toast.error('Окно для фото: введите целое число минут от 0 до 120')`, панель настроек открыта, фокус на поле **[авто]**.
- 400 сервера по этому полю: то же сообщение под полем, панель открывается (`setSettingsOpen(true)`), как сейчас при ошибке адреса.
- Если поле скрыто, проверка не блокирует сохранение (значение пришло с сервера и уже допустимо).

## Поверхность 6. Отказ фото (D-09; показывают фазы 12–13)

Серверная функция «принимается ли фото сейчас» отдаёт код и `uploadClosesAt`; текст строит web по коду (английские строки сервера пользователю не показываются, как в фазе 10). В этой фазе тексты фиксируются, интерфейс фото появится в фазе 12.

| Код | Текст |
|-----|-------|
| `UPLOAD_WINDOW_CLOSED` | `Время для добавления фото закончилось в {HH:mm}. Фото не сохранено.`; если окно закрылось в другой день — `Время для добавления фото закончилось {d MMM} в {HH:mm}. Фото не сохранено.` (то же правило, что в строке «закрыто») |
| `UPLOAD_WINDOW_NONE` | `К этой попытке фото добавить нельзя.` |

Получив `UPLOAD_WINDOW_CLOSED`, строка окна сразу переходит в «закрыто», даже если часы устройства отстают **[авто]**.

## Поверхность 7. Вкладки, сессия и выход (PLAT-01…PLAT-04, D-15…D-20)

Видимого интерфейса нет. Фоновые задачи, остановка API, замок `navigator.locks` на обновление сессии и чистка ключей при выходе не добавляют и не меняют ни одного текста, тоста или экрана. Для аудита — что остаётся как есть:

- Выход: тост в `nav-user` и переход на `/login` как сейчас; ошибки выхода не показываются.
- Несколько вкладок: ни одна вкладка не выходит из аккаунта из-за обновления сессии в соседней; сообщений о синхронизации нет.
- После выхода на общем компьютере следующий ученик при открытии того же теста не получает чужих ответов и тоста `Сессия восстановлена`.
- Тосты `Сессия восстановлена`, `Предыдущая попытка закрыта, начата новая.`, `Осталась 1 минута — тест будет сдан автоматически`, «Не удалось начать тест…» — без изменений.
- CR-05: у теста без лимита после возврата связи сессия создаётся сама, и строка сохранения меняется с `Нет связи с сервером. Ответы сохранены на этом устройстве` на `Ответы сохранены` — тексты индикатора прежние.
- CR-03 (bfcache): видимых изменений нет.
