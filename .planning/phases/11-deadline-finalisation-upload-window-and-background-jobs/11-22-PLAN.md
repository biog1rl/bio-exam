Вторая часть находки A из `11-ARCH-REVIEW.md` (продолжение 11-19): сдача — команда модуля `submitSession`, которая сама решает, когда финализировать; шаги `precheckSubmit` и `submitAttempt` говорят словарём `SessionOutcome` и уходят из публичного интерфейса; сборка фактов попытки (`ScoredAttemptFacts` трижды — `/submit`, финализация, сид) заменена записью результата оценки целиком; сид создаёт попытки командой сдачи. Поведение API не меняется: рефакторинг под защитой тестов (ADR-0003). Требования TIME-01 и TIME-06 закрыты планами 11-04…11-09; план переносит правило сдачи в модуль.

Purpose: после плана все входы попытки (старт, черновик, сдача, судьба, задача) вызывают команды модуля, а маршрут только переводит исход в HTTP; сид не расходится с HTTP-путём.
Tracer — `POST /submit` → `submitSession` → `precheckSubmit`/`submitAttempt` в словаре → `sendSessionOutcome(res, 'submit', …)` → HTTP-наборы сдачи зелёные без правок; расширение: сид через команду, окно фото и гонка без HTTP, ворота с e2e, читающими попытки сида.
Output: правки `commands.ts`, `submit.ts`, `deadline.ts`, `index.ts`, `public.ts`, `e2e-seed.ts`, служебных случаев трёх тестовых файлов, новые случаи `commands.test.ts`.

Решения плана (записать в SUMMARY):
- Смена фикстуры e2e (решение плана): сид идёт через `submitSession`, поэтому засеянные попытки тестов с открытым вопросом (`review-pending-*`, `review-graded-*`) получают `upload_closes_at` = момент сдачи + `photo_upload_window_minutes` теста (по умолчанию 15). Раньше у них было `NULL` — расхождение, отмеченное в обзоре. Строка окна для фото показывается только в исходе сдачи на странице прохождения, поэтому видимых изменений в спеках не ждём; проверка — e2e, читающие попытки сида. `seed.json` не меняется.
- `finalized` или `submitted` во всех шагах сдачи решает `classifySubmitted` из 11-19 по столбцу `submit_source`. Ветка `ClientAttemptConflict` (тот же `clientAttemptId` у попытки другой сессии) читает `submit_source` найденной попытки и тоже идёт через неё, поэтому 409 для попытки `deadline` приходит с полным телом, как сейчас через `readAttemptView`. Клиент не может прислать ключ `deadline:<uuid>` (схема требует UUID, 11-01), отдельного HTTP-теста у этой ветки нет.
- Шаги сдачи остаются внутренними, закрепления гонки «между предпроверкой и транзакцией» импортируют их из `submit.js`; заглушка результата оценки — объект `ok: true` из `scoreSubmission` вместо `ScoredAttemptFacts`.
- `submitAttempt` перегружен: без `expectedDraft` тип исхода не содержит `draft_changed`, поэтому маршрут не знает о нём и не бросает исключение.

Правила плана — общие для фазы 11, в блоке «Правила плана» `11-01-PLAN.md`. Режим исполнения — worktree (`11-EXEC-RULES.md`, раздел «Режим worktree»), если ведущая сессия не сказала иначе.
