Purpose: после дедлайна текст ответа только для чтения (критерий 2 ROADMAP), а часы устройства не решают, когда вышло время (M6).
Tracer — `/start` с `serverNow` → якорь серверного времени → `secondsLeft` и `deadlinePassed` по серверу → `TestRunner` переводит текстовые поля в `readOnly`; расширение: смена закрепления 11-02 (D-12), автоповтор, панель дедлайна, таймер, e2e без связи.
Output: `server-clock.ts`, правки `lifecycle.ts`, `QuestionInput.tsx`, `TestRunner.tsx`, новый `DeadlinePanel.tsx`, тесты `lifecycle-time.test.ts`, e2e `timed-attempt.spec.ts`.

Решения плана (записать в SUMMARY):
- Якорь серверного времени ставится по ответу `/start` (а в 11-12 и 11-14 — по телу 409 и чтению судьбы; в виде попытки `/submit` 200 `serverNow` нет, решение 11-01), не по ответам PATCH черновика: задержка сети на частых PATCH дёргала бы таймер, а в e2e `page.clock` сдвигает часы устройства относительно сервера, и пересчёт по каждому ответу возвращал бы таймер назад. Сервер отдаёт `serverNow` и в PATCH по контракту UI-SPEC (11-06).
- Смещение в кэше сессии не хранится: после перезагрузки судьбу сессии решает сервер (`/start`, в 11-14 — чтение судьбы), а при сбое сети остаётся прежняя проверка по часам устройства.
- Пауза `TIME_UP_PAUSE_MS` и `showTimeUp` сохраняются (UI-SPEC разрешает): панель видна не меньше 1,5 с перед исходом, закрепления `lifecycle-time.test.ts` не меняются.
