<objective>
Форма настроек теста — один модуль без React (находка C, №4 из `11-ARCH-REVIEW.md`; ADR-0005): из сохранённого в форму, из формы в тело PATCH и создания, проверки (включая окно для фото из 11-10) и «изменено ли» — в `test-settings-form.ts`; хук `useTestEditorModel` только вызывает модуль. Поведение редактора не меняется: это рефакторинг под защитой тестов (ADR-0003). Требование TIME-02 (поле окна для фото в настройках) закрыто планом 11-10; план переносит его правила в модуль формы.

Purpose: следующее поле настроек — одна правка в модуле и поле на панели, а не семь файлов, как у окна для фото (`12139cb`); забытое место ловит typecheck, а не «изменено ли» или тихо пропавшее поле запроса.
Tracer — таблица полей → `withSavedSettings` (синхронизация после загрузки) → `settingsChanged` (точка «изменено» и панель сохранения) → `updateSettingsBody` → PATCH → e2e `test-editor.spec.ts`; расширение: проверки и поле окна на панели, тело создания и начальная форма, ворота.
Output: новые `test-settings-form.ts` и тест, правки хука, слоя API, `test-editor-view.ts` и его теста, `test-editor-utils.ts`, панели, `types/index.ts`.

Решения плана (записать в SUMMARY):
- Тип тела задаётся на границе API редактора (`UpdateTestSettingsBody`, `CreateTestBody`), `json?: unknown` в `lib/http/request.ts` общий для всех доменных слоёв и не меняется. `updateTestSettings(testId, form)` и `createTest(form)` сохраняют сигнатуры и строят тело функциями модуля, поэтому закрепление тела PATCH в `test-editor-api.test.ts` не меняется.
- `TestSettings` объявлен в модуле; `TestFormData` в `types/index.ts` расширяет его (`import type`) полями `order`, `scoringRules?`, `questions`.
- `savedSettings`, `settingsDirty`, `settingsOf`, `SettingsFields`, `SavedTestSettings` уходят из `test-editor-view.ts`, их случаи из `test-editor-view.test.ts` переезжают в таблицы модуля отдельным шагом красный → зелёный; `createInitialTestForm`, `normalizeFormPayload`, `getBaseValidationError` уходят из `test-editor-utils.ts`.
- `photo-window.ts` и его тест не меняются: модуль формы использует `photoWindowSaveError` и `hasOpenQuestion`, панель берёт подсказку `photoWindowHint` как раньше.
- Фокус на поле окна, `setTimeout` и открытие панели остаются в хуке (это DOM); модуль отдаёт `{ message, field }`.
- `persistNewTest` вызывается и из `handleSave`, и из `handleAddQuestion` (режим создания, без `handleSave`), поэтому базовая проверка остаётся внутри него: `settingsSaveError(form, { mode: 'create', questionCount: form.questions.length })`, ошибка → `Error(message)` с прежним текстом. В режиме создания вопросов в форме нет, поэтому проверка окна для фото там ничего не добавляет.
- «Отменить изменения» через `withSavedSettings` возвращает и `order` к сохранённому значению (сейчас отмена его не трогает): в интерфейсе `order` не редактируется и всегда равен сохранённому, поэтому видимого изменения нет — сознательное упрощение, записать в SUMMARY.
- `yarn editor:budget` меряет только маршруты редактора вопроса (`scripts/editor-bundle-budget.json`), страница настроек теста в бюджет не входит; проверка нужна только как подтверждение, что общий код не вырос.
