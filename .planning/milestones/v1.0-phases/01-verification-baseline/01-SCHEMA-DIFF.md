## Оценка реальных отличий (для DRZ-01 и Milestone 2)

- **Группа 1 (переклассифицирована в шум платформы).** DRZ-01 не затронут: в схемах `public` и `extensions` нет объектов приложения, которых нет в цепочке. Ограничение скрипта: построчный классификатор не умеет охватывать многострочные тела функций в `$$ … $$`, поэтому такая группа всегда выходит как `реальное отличие` и требует разбора глазами; зафиксировано в `deferred-items.md`. Обработка в следующих фазах не нужна.
- **Группа 2.** DRZ-01 (боевая база != цепочка) формально нарушен только для служебной таблицы мигратора, не для схемы приложения. Причина установлена: до коммита `f9d0e45` (2026-02-26, «переделал миграции на встроенный migration от drizzle») `apply-migration.ts` сам делал `CREATE TABLE IF NOT EXISTS __drizzle_migrations (…, created_at BIGINT NOT NULL)` и писал в `hash` имя миграции. Встроенный мигратор drizzle-orm 0.45.3 создаёт ту же таблицу с `created_at bigint` без `NOT NULL`, но `IF NOT EXISTS` существующую не меняет. Менять боевую таблицу в этом плане не нужно; Milestone 2 решает, переносить её как есть или создавать заново.

## История миграций (public.__drizzle_migrations)

**История боевой базы и репозиторий разошлись по формату записи и одной лишней записью.** Состав миграций покрыт полностью: каждая из 21 миграций цепочки представлена вживую.

- Живых записей: 22; миграций в манифесте: 21
- Совпали по sha256 (контрольная сумма проверена): 7. Это 0014_app_settings, 0015_student_groups, 0016_session_draft_answers, 0017_question_search_documents, 0018_enable_remaining_rls_and_move_pg_trgm, 0019_session_draft_telemetry, 0020_short_answer_variants. `created_at` каждой равен `when` из `_journal.json`.
- Совпали по имени, в колонке `hash` лежит имя миграции, а не sha256 (контрольная сумма **не проверена**): 14. Это 0000_typical_exiles … 0013_drop_user_position_and_show_in_team, включая 0010_question_drafts. Их `created_at` (2026-01-21 … 2026-02-23) не равен синтетическим `when` в журнале (1700000000000 + n·1000), и сравнивать их смысла нет.
- Есть в манифесте, нет вживую ни по sha256, ни по имени: нет.
- **Есть вживую, нет в манифесте: `0010_test_drafts`** (`created_at` 1771698322879, 2026-02-21, на 1 ч 42 мин раньше `0010_question_drafts` и на 0,3 с позже 0009). Файла `0010_test_drafts.sql` в истории git нет, источник записи не установлен. В схеме `public` нет лишних объектов (diff чистый), поэтому запись безвредна для схемы.
- Повторяющиеся записи вживую: нет.

Что это значит:

- **Боевую базу текущий раннер не сломает.** Мигратор drizzle-orm 0.45.3 читает только последнюю запись по `created_at` (сейчас 1784985600000, миграция 0020) и применяет миграции, у которых `when` больше. Лишняя запись и имена вместо sha256 на него не влияют, повторный запуск `drizzle:migrate` на проде ничего не применит.
- **Для Milestone 2 (`plans/beget-migration.md`, п. 3.1.2, «нельзя просто запустить все миграции повторно поверх восстановленной схемы»)** находка подтверждает опасение. Два совместимых пути: (а) восстановить схему и данные из дампа вместе с `__drizzle_migrations` (мигратор увидит 0020 последней и ничего не запустит); (б) собрать схему цепочкой с нуля и данные залить без `__drizzle_migrations`. Смешивать нельзя. Нормализовать записи на проде (заменить имена на sha256, удалить `0010_test_drafts`) — решение Milestone 2, не этого плана.
- Подтверждение «хэши 0000-0013 совпадают» вживую получить нельзя: sha256 там не хранится. Заменой служит равенство схемы: диффа в `public` нет.

## Что сравнение не покрывает

Дамп снят с `--schema=public --schema=extensions --no-privileges`, поэтому не проверены: роли и владельцы, права доступа (GRANT/REVOKE, default privileges), публикация `supabase_realtime`, версии расширений, служебные схемы Supabase (`auth`, `storage`, `realtime`, `vault` и др.), задания `pg_cron`, сами данные и `ANALYZE`-статистика. Для Milestone 2 это отдельная инвентаризация (план 3.1.1).
