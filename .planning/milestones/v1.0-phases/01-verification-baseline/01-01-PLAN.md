<objective>
Make the database boundary safe before anything in this phase touches a database (D-29 is the first task of the phase), and prove it end to end with a disposable PostgreSQL 17 cluster.

Purpose: today `app/server/src/config/env.ts` loads `app/server/.env` with `override: true`, so any process handed a disposable `DATABASE_URL` is silently re-pointed at the live Supabase pooler (research C4). `import 'dotenv/config'` in the runner, seed and bootstrap scripts also fills missing variables such as `SUPABASE_URL` from `.env`, which would let a test seed write to live Supabase Storage. Every later plan (Vitest DB tests, migration check, e2e) depends on this boundary.
Output: one guard module, isolation-aware server entrypoints, the `pg_ctl` harness `scripts/lib/test-db.mjs` with a self-test, and the `scripts/with-test-db.mjs` wrapper.
</objective>
