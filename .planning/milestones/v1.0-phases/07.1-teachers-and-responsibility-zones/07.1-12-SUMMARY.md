## Решения исполнителя (автономно)

1. **Layout `[testSlug]` отказывает только на 403.** 404, 5xx и сбой сети отдают `children`; страница и клиентские компоненты обрабатывают их как раньше. Отдельной проверки `getServerMe` в layout нет: родительский `admin/tests/layout.tsx` уже требует раздел `tests`.
2. **Слаги в URL by-slug кодируются `encodeURIComponent`.** Схема слага `^[a-z0-9-]+$`, для реальных значений запрос не меняется.
3. **Страница попытки:** 404, прочие коды и сбой сети → `notFound()`, как раньше; меняется только 403.
4. **`parseRoleTraits`:** запись без строковых `key` или `name` пропускается, признак не boolean → `null`; пустой `roles` или ни одной пригодной записи → запасной `ROLES_LIST`.
5. **`sectionsCountLabel`** по корзинам UI-SPEC: 1 → «активный раздел», 2–4 → «активных раздела», остальное (0, 5+, 11) → «активных разделов».
6. **`/admin`:** нижний ряд рендерится, только если видны «Служебные экраны» или ссылка «Попытки» (гейт `attempts`). При одном видимом блоке сетка `grid gap-4` без колонок `1.5fr_1fr`, чтобы блок не сжимался. Подпись `admin console`, заголовок, подпись под счётчиком и тексты администратора не менялись.
7. **Текст карточки «Настройки»** у пользователя без `zone.all`, но с `settings.manage` остаётся прежним: в UI-SPEC текста учителя для этой карточки нет.
8. **Иконки карточек и ссылок** сопоставляются по ключу в `page.tsx`; `sections.ts` без React и `lucide-react`.
