# Phase 07.1 — UI Design Contract

> Узкий контракт на девять поверхностей, которые фаза меняет в web: роль «Учитель», закрепление учителей за темой, меню и разделы админки учителя, приглашение ученика, карточка ученика у учителя, поиск учеников для группы, удаление теста с попытками, пустые состояния, отказ по прямой ссылке. Режим автономный, вопросов пользователю не задавалось. Обязательные решения взяты из `07.1-CONTEXT.md` (D-16, D-18, D-20, D-21, D-25 выбраны пользователем 2026-10-04; D-03, D-24, D-26 приняты оркестратором) и `07.1-CLIENT-ANSWERS.md`. Всё остальное выбрано по рекомендованному варианту и помечено **[авто]**. Фаза не вводит новых компонентов `components/ui`, цветов, токенов и npm-пакетов. Web зону не вычисляет (ADR-0001): списки приходят отфильтрованными, кнопки и поля показываются по правам из `/api/auth/me`.

### Гейты интерфейса (одна таблица на фазу)

Каждая поверхность ниже ссылается на гейт по коду. Гейт — только право из `useAuth().can` (клиент) или `me.perms` (сервер). Роль в условиях не участвует (D-04) без исключений: где диалогу администратора нужно знать смысл выбранной роли, он читает признаки `ownsZone` и `groupMember`, которые сервер выводит из прав роли (Поверхность 1).

| Код | Условие | Что открывает |
|-----|---------|---------------|
| G-CAT | `can('zone','all') && can('tests','write')` | каталог: «Новая тема», правка и удаление темы, поле «Учителя», кнопки «Баллы» и «Типы вопросов», создание темы из редактора теста, блок «Начисление баллов» в редакторе теста («Настроить баллы для этого теста», «Настроить типы вопросов») |
| G-ALL | `can('zone','all')` | выбор роли и необязательная группа в приглашении; поле и колонка «Владелец» у групп; кандидаты в группу из `/api/users`; текст «Тема не найдена» |
| G-EDIT | `can('users','edit')` | кнопка `Pencil` и `EditUserDialog` (как сейчас) |
| G-VIEW | `can('users','read') && !can('users','edit')` | карточка ученика только для чтения и блок «Сеансы и вход» на странице `/profile/<login>` |
| G-INV | `can('users','invite')` | кнопка «Пригласить ученика» / «Пригласить», повторная ссылка для неактивных |
| G-SEC | `canAccessSection(perms, section)` | разделы `/admin/*` и карточки на `/admin` |

Учитель (права D-02, без `zone.all` и `users.edit`) проходит G-VIEW, G-INV и G-SEC для `tests`, `attempts`, `users`, `groups`. Администратор проходит все гейты, кроме G-VIEW.

Данные, на которые опирается UI (форма — у планировщика): строки `/api/users` несут все группы пользователя (`groups: { id, name }[]` вместо одного `groupName`, D-19); строки групп у администратора несут владельца (имя учителя или `null`); строки назначений (`/api/tests/:id/assignments`, `/api/users/:id/test-assignments`) несут признак «можно снять».

## Поверхность 1. Роль «Учитель» в создании, приглашении и правке (D-01, D-17)

### Реестр

`ROLE_REGISTRY`: `admin` — «Администратор» (`order: 0`), `teacher` — «Учитель» (`order: 5`), `user` — «Ученик» (`order: 10`). `ROLES_LIST` отдаёт их в этом порядке. Все бейджи ролей (`UserRowItem`, мобильная карточка `UsersTable`) выводят `roleDisplayName`: вместо «Пользователь» появляется «Ученик». Класс `capitalize` у бейджа не меняется.

**Фокус:** выбор роли в диалоге администратора; новая роль «Учитель» стоит между «Администратором» и «Учеником».

### Признаки ролей от сервера (требование к планировщику)

Условия показа в диалогах администратора зависят от признаков роли, которые сервер выводит из прав роли, а не от ключа роли. Web не сравнивает ключ роли ни с литералом, ни с константой.

| Признак | Как сервер его считает | Что по нему делает web |
|---------|------------------------|------------------------|
| `ownsZone` | действующие гранты роли (реестр + `rbac_role_grants`) дают хотя бы одно из `tests.write`, `groups.manage_groups`, `users.invite` и не дают `zone.all`: роль работает в зоне | предупреждения `Учитель без тем` и `Темы и группы перейдут администраторам`, подсказка после приглашения |
| `groupMember` | действующие гранты роли не дают ни одного права управления (`tests.write`, `tests.manage_assignments`, `groups.manage_groups`, `users.read`, `users.edit`, `users.invite`): роль ученика | поле `Группа` в приглашении администратора показывается только для такой роли |

Место: записи списка ролей `GET /api/rbac/roles` (уже под `rbac.read`, есть у администратора) получают поля `ownsZone` и `groupMember` рядом с `key` и `name`. Форма записи и общая функция расчёта (рядом с `normaliseRoleKeys` в `packages/rbac` или в `services/access-policy`) — Discretion планировщика. Учителю список ролей не нужен: его диалог роль не показывает.

Если список ролей не загрузился: роли берутся из `ROLES_LIST` по именам, поле `Группа` показывается для любой роли, предупреждения не показываются. Решение о доступе всё равно принимает сервер.

## Поверхность 7. Удаление теста учителем (D-25, подтверждено пользователем)

**Фокус:** тост ошибки 409 с подсказкой снять публикацию.

Места: `TestsClient.handleDeleteTest`, `TopicTestsClient.handleDeleteTest` (через `TopicTestCard`). Подтверждение — `useUiAlertDialog`, тексты без изменений: `Удалить тест?` / `Тест "{название}" будет удален без возможности восстановления.` / `Удалить` · `Отмена`.

| Ответ | Поведение |
|-------|-----------|
| 2xx | `toast.success('Тест удален')`, список обновляется (как сейчас) |
| 409 | `toast.error` с текстом `error` из тела ответа без изменений: `У теста есть попытки учеников. Снимите публикацию или обратитесь к администратору`. Тест остаётся в списке |
| 403 | `toast.error('Недостаточно прав для этого действия. Обратитесь к администратору.')` |
| прочее | `toast.error('Не удалось удалить тест. Попробуйте ещё раз.')` |

Сейчас обработчик бросает `'Ошибка удаления'` и теряет тело. Новый обработчик читает `{ error }` при 409. Кнопка `Удалить` не прячется заранее: число попыток в списке тестов не приходит. Снятие публикации — существующий переключатель в редакторе теста.

## Ширина 375px

Общее правило для всех поверхностей: на 375px у страницы нет горизонтального скролла; горизонтальный скролл допустим только внутри рамки таблицы (`overflow-auto` у обёртки, как сейчас).
