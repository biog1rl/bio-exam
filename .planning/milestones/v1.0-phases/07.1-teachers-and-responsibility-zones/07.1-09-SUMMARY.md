## Формы ответов для web (07.1-15, 07.1-16, 07.1-18)

- `GET /api/groups/my` (любая сессия) → `{ groups: { id, name }[], group: { id, name } | null }`; `groups` по имени, `group` — первая из них (до выкатки web).
- `GET /api/groups` (`groups.manage_groups`, иначе 403) → `{ groups: { id, name, createdAt, memberCount, owner? }[] }`; `owner: { id, name, firstName, lastName } | null` только при `zone.all`, у учителя ключа нет; пустая зона → `{ groups: [] }`.
- `GET /api/groups/:groupId` → `{ group: { id, name, createdAt, members: { id, name, login, isActive }[] } }`; нет доступа → 403 `{ error: 'Forbidden' }`; несуществующая группа у администратора → 404 `{ error: 'Group not found' }`, у учителя → 403.
- `POST /api/groups { name, memberIds?, ownerId? }` → 201 `{ group }`. Учитель: `ownerId` в теле → 403; не ученик → 400 `{ error: 'В группу учителя можно добавить только учеников' }`; деактивированный ученик → 400 `{ error: 'Деактивированного ученика нельзя добавить в группу' }`. Администратор: `ownerId` не учитель → 400 `{ error: 'Учитель не найден или не активен' }`; при владельце-учителе персонал в составе → 400 `{ error: 'В группе учителя могут быть только ученики', userIds }`.
- `PATCH /api/groups/:groupId { name?, memberIds?, ownerId? }` → 200 `{ ok: true }`; те же 400 и 403; у учителя проверяются только добавляемые id.
- `DELETE /api/groups/:groupId` → 200 `{ ok: true }`; 403/404 как у карточки.
- `GET /api/groups/candidates?q=` (`groups.manage_groups`, иначе 403) → `{ users: { id, name, firstName, lastName, initials, avatarColor, avatarCropped }[] }`, до 20, только активные ученики; `q` после trim короче 2 → 400 `{ error: 'Укажите не меньше 2 символов для поиска' }`.
- `GET /api/groups/owner-options` (`groups.manage_groups` и `zone.all`, иначе 403) → `{ owners: { id, name, firstName, lastName }[] }`.

## Deviations from Plan

### Решения исполнителя (автономно)

1. **R8 на правке состава администратором.** must_haves требуют проверку итогового состава при смене владельца на учителя. Если администратор правит только `memberIds` группы, у которой владелец уже учитель, без проверки он мог бы добавить персонал в зону учителя. Сделано: при `zone.all`, `ownerId` не передан, `memberIds` передан и владелец группы не `null` (из `groupOwners`) — `nonStudentUserIds(memberIds)` пуст, иначе 400 с `userIds`. Правка только названия ничего не проверяет. Строка матрицы `admin PATCH /api/groups/:fresh member teacher`.
2. **404 только для `groupScope.all`.** `canManageGroup` отказывает и на несуществующей группе. После отказа существование проверяется только при `groupScope(req).all` (`groups.manage_groups` и `zone.all`), иначе 403 без раскрытия существования. Так же устроены PATCH и DELETE (у администратора на несуществующую группу теперь 404 вместо 200).
3. **Дубли в `memberIds` у PATCH.** Вставка состава идёт по `new Set(memberIds)`: раньше повтор id давал 500 на первичном ключе.
4. **Проверки состава и владельца в POST — до транзакции**, запись группы, владельца и участников — в одной транзакции. В PATCH текущий состав и владелец читаются в транзакции правки, нарушение возвращается значением до первой записи.
5. **Ответ `POST` содержит `ownerId` записанного владельца** (строка `returning` берётся до `setGroupOwner`, поле подставляется из того же значения).

Других отклонений нет. Комментариев в коде не добавлено, существующие заголовки маршрутов не тронуты. `escapeLikePattern` — локальная копия в `routes/groups/index.ts`, `routes/users/index.ts` не менялся. `lib/constants.ts` не менялся.
