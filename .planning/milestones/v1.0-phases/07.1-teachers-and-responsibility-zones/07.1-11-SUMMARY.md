## Формы ответов для web (07.1-15 … 07.1-17)

`GET /api/users` (`users.read`) → `{ rows, users, total }`, `rows` = `users`, `total` считается тем же условием зоны. Строка:

```
{ id, login, firstName, lastName, name, avatar, avatarCropped, avatarColor, initials, isActive,
  invitedAt, activatedAt, createdAt, createdByName, roles: string[], birthdate, telegram, phone, email,
  groups: { id, name }[],   // все группы, порядок name, id
  groupName: string | null } // имя groups[0], на время выкатки web
```

Без `zone.all` — только участники групп запрашивающего; без групп — `{ rows: [], users: [], total: 0 }`.

`GET /api/users/:userId/test-attempts` (`tests.read`) → `{ attempts: [{ attemptId, testId, testTitle, testSlug, topicSlug, topicTitle, submittedAt, earnedPoints, totalPoints, scorePercentage, passed }] }` — только тесты разделов `testScope`; без `zone.all` у пользователя с ролью из `STAFF_ROLE_KEYS` — `{ attempts: [] }`.

`GET /api/users/:userId/test-assignments` → 403 `{ error: 'Forbidden' }` без `canReadUser`; иначе `{ assignments: [{ testId, assignedAt, testTitle, testSlug, canUnassign: boolean }] }` — только тесты разделов `testScope`.

`GET /api/tests/:testId/assignments` → 403 без `canReadTest`; иначе `{ assignments: [{ userId, assignedAt, name, isActive, login?, canUnassign: boolean }] }`. Ключ `login` есть только у участников групп из `userScope` запрашивающего (при `all` — у всех); у остальных ключа нет.

`canUnassign` = `canAssign(test, user)` и (`zone.all` или `assigned_by` = запрашивающий).

`POST /api/users/:userId/test-assignments { testId }`, `POST /api/tests/:testId/assignments { userId }`: 400 при плохом теле, затем 403 без `canAssign`, иначе `{ ok: true }`. `DELETE` в обоих роутерах: 403 по правилу снятия, иначе `{ ok: true }`. `POST /api/tests/:testId/assignments/group/:groupId`: 403 без `canWriteTest` и `canManageGroup`, иначе `{ ok: true, assigned }`.

`PATCH /api/users/:id/group` (`users.edit`): тело `{ groupIds: uuid[] }` (до 100) или прежнее `{ groupId: uuid | null }`; 400 `{ error: 'Invalid groupId', details }` при плохом теле; 404 `{ error: 'Группа не найдена' }`, если хотя бы одной группы нет; 400 `{ error: 'В группу учителя можно добавить только учеников' }` или `{ error: 'Деактивированного ученика нельзя добавить в группу' }` при входе в группу с владельцем-учителем; иначе `{ ok: true }`, членства заменяются полным набором.

`PATCH /api/users/:id`: зона (закрепления разделов, владение группами) освобождается в той же транзакции при `isActive: false` и при изменении набора ролей на набор без роли с `ownsZone`. Запрос без `roles` роли и зону не трогает.

- `POST …/group/:groupId` на несуществующую группу отвечает 403 (раньше 200 `assigned: 0`): `canManageGroup` возвращает false.
- Acceptance Task 1 называет tracer `teacherA POST /users/:s1/test-assignments tY`; в матрице это строка `teacherA POST /users/:own/test-assignments tY` (свежий ученик в G, решение 07.1-05), она удалена из `KNOWN_DEFECTS` в Task 1.
- `groupIds` в `PATCH /api/users/:id/group` ограничен 100 элементами (`z.array(...).max(100)`).
- `groupName` берётся из `groups[0]`, отдельный подзапрос с `limit 1` без сортировки удалён.
