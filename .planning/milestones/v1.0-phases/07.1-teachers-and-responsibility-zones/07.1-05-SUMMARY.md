## Решения исполнителя (автономно)

- Формат id: роутер пользователей — `/users...` (иначе не проходит regex плана `GET \/users rows`), роутер назначений теста — `/api/tests/...` (заметка 5). В id нет `]` и запятых.
- Поле `groups` у строки s1 вынесено в отдельный id `admin GET /users groups` (07.1-11), чтобы 07.1-06 мог удалить id `… GET /users rows`.
- `:own` — свежий ученик в G, `:ungrouped` — свежий ученик без групп (по образцу заметки 6). Acceptance 07.1-11 называет tracer `teacherA POST /users/:s1/test-assignments tY`; в матрице это `teacherA POST /users/:own/test-assignments tY` (цель — свежий ученик в G по Task 1).
- `admin PATCH /users/:fresh/group groupIds`: ученик сначала только в G, тело `[G, GA]`, ожидание ровно {G, GA}. Строка прежнего тела `{ groupId: G }` начинает с ученика в G и GA.
- Строки `/api/users` идут с `?limit=500`, чтобы свежие пользователи при перемешивании не вытеснили людей мира с первой страницы.
- Поиск вопросов — `q='половая клетка'`, остальные категории — `q` = префикс мира `tzsrch`; `limit=25`.
- teacherA в попытках поиска ожидает {s1X, s2X, teacherAX}: 07.1-08 фильтрует по разделу теста.

## Deviations from Plan
