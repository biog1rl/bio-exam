# Phase 07.1 Plan 18: группы учителя и администратора, группы в профиле, пустые состояния Summary

Учитель в `GroupSheet` ищет учеников по имени через `GET /api/groups/candidates?q=` (от 2 символов, задержка 300 мс, `Command shouldFilter={false}`): строки «Введите минимум 2 символа», «Ищем…» с `role="status"`, «Никого не найдено. Новых учеников приглашают в разделе «Пользователи».», «Не удалось выполнить поиск. Попробуйте ещё раз.»; пункт — имя без логина, `value` пункта — id. `UserStatusFilter` и «Владелец» у учителя не рендерятся, `ownerId` в теле не отправляется. Чипы — участники группы и выбранные кандидаты (имена хранятся в состоянии), `Badge` с кнопкой `X` и `aria-label="Убрать {имя}"`. Администратор работает с `/api/users` как раньше и выбирает владельца («Администраторы» или активный учитель из `/api/groups/owner-options`) с подсказкой UI-SPEC. Ошибки сохранения: 400, 403 и прочее — тексты UI-SPEC. В списке групп у администратора колонка «Владелец», у учителя без групп — блок с текстом и кнопкой «Создать группу». Профиль ученика показывает «Группы» с бейджем на каждую. Дашборд и `/admin/attempts` у учителя без `zone.all` дают тексты пустых состояний Поверхности 8.

## Deviations from Plan

### Решения исполнителя (автономно)

1. **Ошибка поиска кандидатов.** Общий `fetcher` в `GroupSheet` не бросает ошибку на не-2xx, поэтому строка ошибки UI-SPEC никогда бы не показалась. Для `/api/groups/candidates` добавлен `strictFetcher` и `shouldRetryOnError: false`. Это закрывает у учителя отложенный пункт 07-11 («пустой список при 403»); у администратора `/api/users` и состав группы по-прежнему без показа ошибки (план описывает ошибку только для поиска).
2. **`candidatesState` и `groupSavePayload`** — две чистые функции сверх перечня плана: состояние списка поиска (подсказка, поиск, ошибка, пусто, список) и тело POST/PATCH без `ownerId` у учителя. Обе под тестом.
3. **`personLabel` без имени** возвращает `—`; у администратора чип участника без имени показывает логин, как было.
4. **Чипы администратора** собираются из `selectedIds`, а не из списка, отфильтрованного по статусу: раньше неактивные участники пропадали из чипов при фильтре «Активные», хотя оставались в составе.
5. **Суффикс « · приглашён»** только у учителя.
6. **Владелец при правке** берётся из строки списка (`owner`), потому что `GET /api/groups/:id` владельца не отдаёт; `ownerId` у администратора отправляется всегда. Если текущий владелец не входит в `owner-options` (неактивен), он остаётся пунктом списка, чтобы сохранение не сбросило его молча.
7. **Пустой текст дашборда** выбирается по `can('zone','all')` прямо в разметке, текст попыток — локальной `emptyAttemptsText` в `AdminAttemptsClient`; заголовок «Попыток пока нет» не менялся.
8. **Кнопка «Создать группу» в пустом состоянии** — `Button` по умолчанию (accent по UI-SPEC: вариант `default`), `w-full mob:w-auto`.

Других отклонений нет. Комментариев в коде нет (прежние JSX-комментарии в `GroupSheet` удалены вместе с переписанной разметкой). Пакетов не добавлялось, `use-debounce` не тронут.
