## Phase Boundary

Файлы, содержимое вопроса, ассеты и справочник пользователей.

- **Хранилище (сервер).** Один модуль хранилища с портом и тремя адаптерами: Supabase, локальный том, in-memory для тестов. Внутри модуля: нормализация ключей, containment, правило «ключ → URL», полный обход списков, единые режимы ошибок. Маршруты не трогают `fs` и не строят пути. Запасной путь `../web/public/uploads` удаляется. Один контрактный набор тестов на всех адаптерах.
- **Содержимое вопроса (сервер).** Один модуль владеет жизненным циклом вопроса: создать, править, перенести, удалить, прочитать, упорядочить. Пять частей вопроса согласованы: строка в БД, версии ключа, файлы промпта и пояснения, документ поиска, путь от slug. Обработчики `routes/tests/index.ts` и `public.ts` делегируют модулю. Сюда входят переименование slug теста и темы (с переносом файлов), один механизм непрерывного порядка, D6, слияние двух блоков чтения у администратора, `settings.json` и `answer_keys.json` (QCON-05).
- **Ассеты.** Загрузка, удаление и список медиатеки требуют права на работу с содержимым; имена новых объектов `images/<hex>.webp`. Чтение файлов по сессии ограничено пространствами имён картинок. Ссылки на картинки в промптах и пояснениях учитываются индексом: ZIP теста включает их, медиатека не удаляет используемую картинку. Устаревшие формы ссылок продолжают открываться.
- **Web.** Получает готовые URL картинок от API. Регулярка URL Supabase и знание раскладки хранилища уходят из web. Медиатека показывает отказ удаления используемой картинки и прячет загрузку и удаление без права.
- **Справочник.** Роль `user` теряет `users.read`. Полный список `GET /api/users` остаётся у админского права. Обычному пользователю доступен ограниченный поиск с минимальными полями.

Требования: STOR-01 … 05, QCON-01 … 05, ASSET-01 … 02, PRIV-01 … 03 (`.planning/REQUIREMENTS.md:85-107`). Источник: ADR-0004, ADR-0005, `plans/011-architecture-deepening.md` §2 C3, C4, дефект D6, `plans/006-assets-user-privacy.md`, `plans/beget-migration.md` §3.2-3.3.

Видимое поведение меняется:
- обычный пользователь получает 403 на `GET /api/users`;
- загрузка, удаление и список медиатеки — только с `tests.write`;
- удаление картинки, на которую ссылается вопрос или черновик, отклоняется;
- ZIP теста и темы содержит картинки вопросов; `answer_keys.json` больше не пишется в хранилище;
- переименование slug темы переносит файлы. Неудачный перенос при переименовании теста или темы отменяет переименование, а не оставляет предупреждение;
- при недоступном хранилище чтение вопроса отвечает ошибкой, а не пустым промптом;
- файловый маршрут перестаёт отдавать `.md` и `.json` из `topics/`.

Что НЕ входит:
- Потоковый ZIP с backpressure и отменой — Phase 8 (PERF-04). Ограниченная параллельность чтения промптов как отдельная оптимизация — Phase 8 (PERF-02). В фазе 7 модуль остаётся единственным местом чтения, параллельность прежняя.
- Поиск пользователя по id или login для администратора (D7) и типизированные запросы на web — Phase 8 (HTTP-01 … 04). Нарезка роутера — Phase 8 (DECOMP-*).
- Перенос API в route handlers Next — Out of Scope (ADR-0001).
- Включение локального адаптера на проде, перенос объектов из Supabase и массовая перепись ссылок в контенте и в `users.avatar` — Milestone 2 (`plans/beget-migration.md` §3.2-3.3).
- Редизайн медиатеки, публичные профили, редактор аватара для всех — Out of Scope (план 006, Phase 4 Deferred).
- Чтение промптов и ключей внутри вида попытки (SCORE-02) — Phase 5. Фаза 7 меняет там только источник текста промпта и пояснения: вместо локального чтения файла — вызов модуля.
- Удаление legacy `TestScoringRules` (Phase 3 D-19, Deferred). Поля `scoringRules` и `useGlobalScoringRules` в генерируемом `settings.json` остаются как сейчас.

### Хранилище: порт, адаптеры, ключи (STOR-01 … 04)
- **D-01 [авто]: порт и три адаптера в `services/storage`.**
  - Порт содержит операции, которые реально используются:
    - запись буфера или текста с MIME, Cache-Control и флагом upsert;
    - чтение: буфер с MIME или текст; отсутствие объекта — `null`;
    - проверка существования;
    - пакетное удаление; отсутствующие ключи не ошибка;
    - копирование объекта;
    - список по префиксу (прямой и рекурсивный) с полным обходом, метаданными (размер, время создания), пагинацией и сортировкой для медиатеки;
    - URL по ключу (D-06).
  - Адаптер Supabase — текущий код `storage.ts` с пагинацией `list` (D-04) и серверным `copy` SDK вместо download+upload в `moveDirectory` (`storage.ts:701-733`).
  - Локальный адаптер — текущий локальный режим. В него добавляются список с метаданными (сейчас `listFilesWithMeta` бросает «not supported», `storage.ts:879`) и URL по ключу.
  - In-memory адаптер — для тестов модулей и маршрутов. Заменяет самодельную подделку `uploads.test.ts:21-30` и умеет инъекцию сбоев: «упасть на записи, копировании или удалении ключа X».
  - Выбор адаптера:
    - `STORAGE_DRIVER=local` → локальный;
    - `STORAGE_DRIVER=supabase` или переменная не задана, но заданы `SUPABASE_URL` и `SUPABASE_SERVICE_KEY` → Supabase (так работает прод сейчас, env Vercel не меняется);
    - иначе — явная ошибка конфигурации при первом обращении к хранилищу, без тихого запасного пути;
    - в изолированном процессе Supabase запрещён всегда.
  - Удаляются запасной путь `../web/public/uploads`: `assertLegacyUploadsAllowed`, `LOCAL_UPLOAD_DIR` в `assets.ts:14-15`, `UPLOAD_DIR`/`/tmp/avatars` в `avatar.ts:19-29`, ветка `moveDirectory` `storage.ts:735-782`, локальная ветка `POST /:id/assets`. Удаляются также статика `/uploads` в `app.ts:86-89` и rewrite `/uploads/:path*` в `app/web/next.config.ts:34`.
  - Закрывает блокер STATE «[Phase 1 → Phase 7] WR-04»: загрузки в изолированном режиме идут через локальный или in-memory адаптер.
  - Новых ключей env нет; комментарии `app/server/.env.example:59-65` описывают значение `supabase` и порядок выбора.
- **D-02 [авто]: ключи и containment — одна функция нормализации в модуле, общая для всех адаптеров.**
  - Ключ — относительный POSIX-путь из непустых сегментов. Отклоняются (ошибка ключа):
    - ведущий `/` или `\`, буква диска;
    - `\`, NUL и управляющие символы;
    - пустые сегменты (`//`);
    - сегменты `.` и `..`, в том числе после процентного декодирования. Декодирование повторяется до неподвижной точки, не больше 3 раз; `%2e%2e`, `%252e%252e` отклоняются.
  - Для Supabase правило то же: клиент нормализует `..` в URL пути, и ключ ушёл бы в чужое пространство имён.
  - Для локального адаптера сохраняется проверка realpath и symlink (`storage.ts:121-196`).
  - Пространства имён и политика задаются в модуле:
    - `images/` — общие картинки промптов: запись через сервис ассетов, чтение по сессии;
    - `topics/` — содержимое вопросов: только модуль содержимого вопроса. Исключение — картинки в `topics/*/*/assets/` (устаревшие загрузки теста): чтение по сессии;
    - `avatars/` — аватары.
  - «Чужой префикс» — ключ вне пространства имён, допустимого для операции: имя бакета в начале (`main/...`), `storage/v1/...`, URL другого хоста или бакета, `topics/...` в удалении медиатеки. Чужой префикс отклоняется до обращения к адаптеру.
- **D-03 [авто]: единые режимы ошибок.**
  - Типизированные ошибки модуля:
    - ключ некорректен или выходит за пространство имён → 400;
    - объект не найден → `null` при чтении; 404 там, где маршрут отдаёт файл;
    - объект уже существует при `upsert: false` → конфликт;
    - хранилище не настроено или недоступно после повторов → ошибка 5xx, а не `''`.
  - `readFile` больше не возвращает `''` при ошибке (`storage.ts:368-385`). `readFilesParallel` не прячет ошибки в `''` (`:441-447`). `readJson` не прячет ошибки разбора в `null`.
  - Повторы с экспоненциальной задержкой живут внутри адаптера Supabase.
  - Отсутствие файла промпта у вопроса — по-прежнему пустой текст (решает модуль содержимого, D-08). Недоступность хранилища — ошибка запроса.
- **D-04 [авто]: полный обход и метаданные.** Supabase `list` без `limit` отдаёт 100 записей, поэтому сейчас обрезаются `listFiles`, `listFilesRecursive`, `deleteDirectory`, `moveDirectory` и `createZip` на каталогах больше 100 объектов (`storage.ts:627-669`). Подсчёт `total` у медиатеки идёт одним запросом с `limit: 10000` (`:903-906`). Адаптер обходит страницы до конца. Контрактный набор проверяет 150 объектов в одном каталоге, а подделка клиента Supabase воспроизводит лимит 100 по умолчанию. Сортировка медиатеки (по `created_at` убыв.), пагинация и поля ответа `GET /api/docs/assets` не меняются.
- **D-05 [авто]: контрактный набор.**
  - Один набор `describe.each` по адаптерам: локальный (временный каталог в `os.tmpdir()`), Supabase поверх подделки клиента `@supabase/supabase-js` и in-memory.
  - Набор проверяет:
    - запись и чтение, upsert и конфликт;
    - отсутствие объекта;
    - удаление отсутствующего;
    - copy;
    - полный обход больше 100 объектов;
    - метаданные и пагинацию;
    - URL по ключу;
    - отказ на traversal-входах: `../`, `..%2f`, `%2e%2e`, `%252e%252e`, абсолютные пути, `\`, NUL, `main/…`, URL Supabase как ключ.
  - Тесты symlink — только у локального адаптера: они остаются из `storage.local.test.ts`.
  - Живой Supabase в `yarn verify` не запускается. Реальная проверка адаптера Supabase — preview Vercel (`<specifics>`).
- **D-06 [авто]: правило «ключ → URL» и файловый маршрут (STOR-04).**
  - URL картинки — маршрут приложения `/api/docs/assets/proxy?path=<key>&cacheNonce=…`, как сейчас (`assets.ts:25-27`), на обоих адаптерах. URL аватара на адаптере Supabase — публичный URL, как сейчас; на локальном — тот же маршрут приложения. Правило живёт в модуле.
  - `GET /api/docs/assets/proxy` и `GET /api/docs/assets/signed` проверяют сессию, как сейчас. Дополнительно они принимают только ключи картинок с расширением изображения в пространствах `images/`, `topics/*/*/assets/` и `avatars/`. `.md`, `.json` и остальное содержимое `topics/` маршрут не отдаёт. Сейчас по сессии читается любой ключ, `isSafeStoragePath` (`assets.ts:19-23`) режет только traversal. Студент может прочитать `topics/<t>/<test>/answer_keys.json` (его пишет экспорт, `index.ts:2395`, `:2442`) и `explanation.md`/`prompt.md` неопубликованных тестов.
  - `GET /api/docs/assets/signed` становится разрешением ссылки. Вход — любое значение `src` из контента: ключ, URL Supabase своего бакета (`/storage/v1/object/public|sign/<bucket>/…`), `/uploads/images/…`, `/uploads/tests/<t>/<s>/assets/…`, `uploads/…`, URL `/api/docs/assets/proxy?path=…`. Выход — `{ signedUrl }` с готовым URL. Для внешних `http(s)` значение возвращается как есть. Поле ответа не меняется, параметр `path` сохраняется.
  - Web:
    - `lib/image-signed-url-cache.ts` теряет `SUPABASE_STORAGE_OBJECT_RE`, `getStoragePathFromSupabaseUrl`, `getStoragePathForImageSrc` и `isStoragePath`. Остаётся одна функция «src → URL через API» с кэшем; `data:` и `blob:` используются как есть;
    - `MdxRenderer.tsx` теряет `normalizeImageSrc` (`:39-43`);
    - `image-component.tsx:86` больше не проверяет `/storage/v1/`;
    - `TestRunner.tsx:93-110`, `:572-587` (prefetch) берёт src без `isStoragePath`.
  - Web не знает раскладку хранилища (D-25 проверяет это охранным тестом).
- **D-07 [авто]: аватары через модуль.**
  - Новая загрузка пишет в `users.avatar`/`avatar_cropped` ключ `avatars/<userId>/<hex>.<ext>` вместо URL.
  - Один серверный перевод «значение из БД → URL» применяется во всех ответах с аватаром: `GET /api/users` (`users/index.ts:53-54`), `/api/auth/me` (`auth/me.ts:31-32`), профиль (`users/profile.ts:92`). Перевод принимает ключ, публичный URL Supabase своего бакета, `/uploads/avatars/…` и посторонний URL (пропускается как есть).
  - Удаление прежнего аватара извлекает ключ той же функцией модуля вместо регулярки `avatar.ts:190-196`.
  - Обновление только кропа и `DELETE /api/users/avatar` идут через модуль на любом адаптере. Сейчас на Supabase они читают и удаляют `../web/public/<URL>` (`avatar.ts:317-364`, `:385-417`): кроп без нового файла падает, удаление оставляет объекты в бакете.
  - Существующие значения в БД не переписываются (без миграции данных).
  - `PATCH /api/users/profile` (`profile.ts:18`, `:78`) перед записью пропускает `avatar` через ту же функцию модуля «URL → ключ». Причина: `ProfileClient.tsx:161-164` отправляет `{ ...profileData }`, а там `avatar` — URL из `/api/auth/me` (`:89`, `:120`). Без этого первая правка профиля переписала бы ключ обратно в URL. Схема `z.string().url()` и форма API не меняются. Посторонний URL пишется как есть. Планировщик подтверждает это поведение тестом.
  - Тесты, которые переключает план аватаров: `routes/uploads.test.ts:203-238`. Подделка `getPublicUrl → https://storage.test/…` (`:28`) и ожидания `reply.body.avatarUrl`/`avatarCroppedUrl` (`:224-225`) переходят на in-memory адаптер; в БД ожидается ключ, в ответе — URL по правилу модуля.
  - Мёртвый `components/users/AvatarUpload.tsx` (вызывает несуществующий `/api/users/upload/avatar`, не импортируется) удаляется, если `codegraph` это подтверждает.

    2. транзакция БД: строка, ключ ответа, указатели `prompt_path`/`explanation_path`, документ поиска, индекс ссылок D-17;

### Требует подтверждения пользователя (фазу не блокирует)
1. **Инвентаризация хранилища на проде (STOP ASSET-02, D-19).** Read-only в SQL-консоли Supabase:
   ```sql
   SELECT split_part(name, '/', 1) AS prefix, count(*)
   FROM storage.objects WHERE bucket_id = 'main' GROUP BY 1 ORDER BY 2 DESC;

   SELECT count(*) FILTER (WHERE name LIKE '%/answer_keys.json') AS answer_keys,
          count(*) FILTER (WHERE name LIKE '%/settings.json') AS settings,
          count(*) FILTER (WHERE name LIKE 'topics/%/assets/%') AS test_assets
   FROM storage.objects WHERE bucket_id = 'main';
   ```
   Префикс вне `images`, `topics`, `avatars` → стоп и решение до деплоя D-06. Ссылки в тексте промптов покажет скрипт D-17 без флага записи.
2. **Публичность бакета (возможная дыра уже сейчас).** `SELECT id, public FROM storage.buckets;`. Если `main` публичный, сохранённые `answer_keys.json` (п. 1) и промпты читаются без входа по пути `…/storage/v1/object/public/main/topics/<topic>/<test>/answer_keys.json`. Решение пользователя (вне кода фазы): сделать бакет приватным, а аватары отдавать маршрутом приложения (D-06 это уже умеет на локальном адаптере), либо вынести аватары в отдельный публичный бакет. До решения — удалить сохранённые `answer_keys.json` скриптом сверки (D-27).
3. **Файловый маршрут только для картинок (D-06; дыра существует сейчас).** Сейчас любой вошедший, включая студента, читает через `/api/docs/assets/proxy?path=…` любой ключ бакета: `answer_keys.json` после экспорта с ответами, промпты и пояснения неопубликованных тестов. После фазы `/proxy` и `/signed` перестают отдавать `.md`, `.json` и прочее из `topics/`. Если какой-то клиент читает так промпты, он сломается. В web таких вызовов нет.
4. **Права медиатеки (D-14).** Список, загрузка и удаление в медиатеке — только с `tests.write` (сейчас любой вошедший). Для ролей `admin` и `user` редактор доступен только admin, видимых изменений нет. Меняется для переопределений.
5. **Отказ удаления используемой картинки (D-16).** Новый ответ 409 и текст в диалоге. До бэкфилла индекса удаление в медиатеке отклоняется полностью.
6. **ZIP (D-13, D-18).** В архиве появляются `images/…` и, при пропусках, `missing-files.txt`. `settings.json` генерируется заново (поле `updatedAt` = время изменения теста). `answer_keys.json` берётся из памяти и есть только при `withAnswers=true`. Сохранённые ранее копии в архив не попадают. Этот состав становится базой сравнения для потокового ZIP в Phase 8.
7. **Раскладка файлов вопроса (D-09, D-10).**
   - Новые и отредактированные промпты пишутся в `prompt-<rev>.md`/`explanation-<rev>.md` вместо `prompt.md`/`explanation.md`.
   - Переименование slug темы начинает переносить файлы.
   - Неудачный перенос при переименовании теста отменяет переименование; сейчас — предупреждение «Изображения не были перемещены».
   - Read-only проверка устаревших указателей. Запрос годится только до выкатки: после D-09 каноническим становится `prompt-<rev>.md`.
   ```sql
   SELECT count(*) FILTER (WHERE prompt_path IS NULL) AS no_prompt,
          count(*) FILTER (WHERE prompt_path !~ '^topics/[^/]+/[^/]+/questions/[0-9a-f-]{36}/prompt\.md$') AS noncanonical
   FROM questions;
   ```
8. **Порядок вопросов (D-11).** Read-only, сколько тестов с дырами или дублями (они выровняются при следующей записи в тест):

   ```sql
   SELECT count(*) FROM (
     SELECT test_id FROM questions GROUP BY test_id
     HAVING count(*) <> count(DISTINCT "order") OR max("order") <> count(*) - 1 OR min("order") <> 0
   ) t;
   ```
9. **Справочник (D-20, D-21).**
   - Роль `user` теряет `users.read`: `GET /api/users` даёт ей 403.
   - Появляется `GET /api/users/directory` — поиск активных пользователей по имени с минимальными полями для любого вошедшего.

    ```sql
    SELECT CASE WHEN avatar LIKE 'http%' THEN 'url' WHEN avatar LIKE '/uploads/%' THEN 'legacy_local' ELSE 'key' END AS kind, count(*)
    FROM users WHERE avatar IS NOT NULL GROUP BY 1;
    ```
    (то же для `avatar_cropped`). Кроп без нового файла и удаление аватара начинают работать на Supabase и удалять объекты.
11. **`POST /api/tests/:id/assets` (D-15).** Web его не вызывает; в фазе он переводится на общий сервис ассетов (ключи `images/…`). Удалить маршрут — решение пользователя (прецедент Phase 3 D-19).
