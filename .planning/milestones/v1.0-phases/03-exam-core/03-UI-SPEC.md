## Разбор: `sequence_digits` (D-07, D-08)

Визуальный акцент: первая красная или янтарная ячейка ряда притягивает взгляд первой, строка `Ошибок: N` — вторая по приоритету. Цифра внутри ячейки помечается `aria-hidden`, вердикт озвучивает `sr-only`-текст, чтобы скринридер не читал цифру дважды.

Файл: `app/web/components/tests/attempt-review/QuestionAnswerReview.tsx`, ветка `TextAnswerReview`. Тот же компонент показывает разбор администратору (`AttemptQuestionsList.tsx`) и студенту сразу после submit (`TestRunner.tsx`), поэтому изменение единое для обоих.

### Условия показа (не меняются)

Строка числа ошибок и подсветка показываются, когда ключ виден зрителю или ответ верен: `correctAnswer != null || isCorrect`. Иначе (ключ скрыт, ответ неверен) разбор остаётся как сейчас: только строка ответа, ни числа ошибок, ни подсветки.

### Точный текст

| Элемент | Текст |
|---------|-------|
| Число ошибок | `Ошибок: N` (N — число ошибок адаптера exam-core, та же функция, что оценивает submit) |
| Склонение | не требуется: форма «Ошибок: N» с двоеточием грамматична для любого N (0, 1, 2, 5, 11, 21). Ничего не склоняется |
| Нуль | `Ошибок: 0` |
| Пустой ответ | строка ответа `Нет ответа` (как сейчас), затем `Ошибок: K`, где K — длина ключа; ячеек нет |
| Подсказка о перестановке | `Соседняя перестановка считается одной ошибкой.` (только если есть вердикт `swapped`) |
| Заголовок карточки ответа | не меняется: `Ответ студента` + `· верно` / `· частично` / `· неверно` по сохранённым `isCorrect` и `earnedPoints` (D-06) |
| Карточка «Правильный ответ» | не меняется |

`Ошибок: N` выводится одним текстовым узлом (`{`Ошибок: ${errors}`}`), потому что e2e читает его регулярным выражением `/Ошибок: (\d+)/` (D-18). Строка остаётся в `<p className="mt-2 text-xs">`, на месте прежней «Совпало позиций: X / N».

Строка ответа (`studentLines`, например `2314`) остаётся простым текстом `<p>` над рядом ячеек: e2e и копирование читают её буквально (`review.spec.ts:103` ждёт `2314`). Ряд ячеек — дополнительный, не замена (принято автономно: дублирование цифр дешевле, чем поломка текстового контракта).

### Подсветка позиций

Ряд ячеек рисуется только когда число ошибок больше 0, ответ непуст и ключ виден. При `Ошибок: 0` весь ответ и так в зелёной карточке, ряд не нужен.

Один вердикт на единицу ошибки по D-07: `correct`, `wrong`, `missing`, `extra`, `swapped`. Пара соседних переставленных позиций даёт две ячейки `swapped` и одну единицу ошибки, поэтому число подсвеченных ячеек может быть больше N, и подсказка о перестановке это объясняет.

| Вердикт | Ячейка | Цвет (классы выше) | Пиктограмма | Текст для чтения с экрана |
|---------|--------|--------------------|-------------|---------------------------|
| `correct` | цифра студента | зелёный | `Check` | `позиция {i}: верно` |
| `wrong` | цифра студента | красный | `X` | `позиция {i}: неверно, ожидалась {цифра ключа}` |
| `swapped` | цифра студента (обе позиции пары) | янтарный | `ArrowLeftRight` | `позиция {i}: переставлена местами с соседней` |
| `extra` | лишняя цифра студента сверх длины ключа | красный | `X` | `позиция {i}: лишняя цифра` |
| `missing` | пустая ячейка вместо недостающей цифры, `border-dashed`, содержимое `—` | красный | `Minus` | `позиция {i}: цифра пропущена, ожидалась {цифра ключа}` |

Разметка ячейки: `inline-flex size-10 items-center justify-center gap-1 rounded-xl border font-mono text-base font-medium`, внутри цифра и пиктограмма `size-3` (`aria-hidden="true"`), смысл вердикта несёт `<span className="sr-only">` с текстом из таблицы. Контейнер: `<div role="list" aria-label="Разбор по позициям" className="mt-3 flex flex-wrap gap-2">`, ячейки: `role="listitem"`. Рисунок и сам текст `sr-only` дают два канала помимо цвета: форма и пиктограмма (видящим), текст (скринридеру). Ключ в тексте для `wrong` и `missing` показывается только когда `correctAnswer != null` (при `isCorrect` с скрытым ключом ячеек нет, так как `Ошибок: 0`).

Подпись над рядом не нужна: `aria-label` на контейнере и пиктограммы достаточны. Отдельная легенда не вводится (принято автономно): единственное неочевидное правило — перестановка — описано подсказкой.

### Мобильная версия (< 1024px, `tab`)

- Карточки остаются в существующей сетке `grid gap-3 sm:grid-cols-2`: на узком экране «Ответ студента» и «Правильный ответ» стоят друг под другом.
- Ряд ячеек переносится (`flex-wrap`), размер ячейки фиксирован 40px, горизонтального скролла нет. Последовательность длиной до 12 цифр помещается в два ряда на ширине 375px.
- Пиктограмма в ячейке остаётся видимой на любой ширине (она носитель смысла, не декор), подсказка и «Ошибок: N» переносятся как обычный текст.

### Что не меняется в разборе

- `ChoiceAnswerReview` (`Выбрано: …`, подписи `Выбран · верно`, `Верный ответ · пропущен` и т.д.) — текст и цвета без изменений. Для `single_choice` и `multi_choice` вердикты по вариантам уже подсвечены; D-07 их не перерисовывает.
- `MatchingAnswerReview`: `Верных пар: X / N` и подписи `Верно` / `Неверно · правильная пара: …` без изменений (D-08).
- `short_text` в разборе: одна часть, карточка и подписи как сейчас, числа ошибок нет.
- Верхнеуровневые данные разбора (`AttemptReviewSummary`, `AttemptReviewHero`, `AttemptReviewNav`, статус вопроса, баллы) — из сохранённых `results`, не пересчитываются (D-06).
- Попытки до деплоя `04c621c`: разбор покажет `Ошибок: 1` при сохранённых 0 баллах; пояснение в интерфейсе не добавляется, политика — Phase 5, SCORE-05 (принято автономно).
- Описание метрики `hamming_digits` в админке (`admin/tests/types/index.ts:100`) дополняется: `Считаются несовпадения по позициям и разница длины. Соседняя перестановка при длине больше 3 считается одной ошибкой.` Подпись `MISTAKE_METRIC_LABELS.hamming_digits` («Позиционные ошибки в последовательности») не меняется.

## Редактор вопросов: ошибки проверки и `short_text` (D-09, D-13, D5)

### Где показываются ошибки (принято автономно: существующий паттерн)

Без изменений в механике: ошибка проверки при сохранении показывается одним `toast.error(message)` из `sonner`, запрос не уходит.
- Страница вопроса: `QuestionEditorPageClient.tsx`, `handleSaveQuestion`: `validateQuestion(...)` → `toast.error` (`:431-433`).
- Создание теста с вопросами: `getCreateQuestionsValidationError` → `throw new Error` → `toast.error(err.message)` в `useTestEditorModel.ts`.
- Отказ сервера (если запрос всё же ушёл, например с прямым вызовом API): тот же `toast.error(err.message)` (`:474`), текст приходит из того же адаптера.

Inline-ошибки под полем, красная рамка поля, `aria-invalid` и `Alert` в редакторе не вводятся: в редакторе нет такого паттерна, а правило D-13 («тексты ошибок из одного источника») выполняется общим текстом. Показывается первая найденная ошибка (как сейчас), без списка.

После ошибки состояние формы не сбрасывается: введённые варианты, ключ и порядок остаются, фокус не перемещается.

### Тексты (источник — адаптер exam-core, формулировка web-редактора, D-13)

Тексты, которые уже есть в web, сохраняются дословно (преподаватель их знает); сервер переходит на те же формулировки без англоязычных `correct`/`left/right`.

| Правило | Текст |
|---------|-------|
| Тип не настроен | `Тип вопроса не настроен в БД` |
| Пустая формулировка | `Введите текст вопроса` |
| Выбор: мало вариантов (по умолчанию) | `Добавьте минимум 2 варианта ответа` |
| Выбор: пустой текст варианта | `Заполните все варианты ответа` |
| `single_choice`: ключ не выбран | `Выберите правильный ответ` |
| `multi_choice`: ключ пуст | `Выберите правильные ответы` |
| Сопоставление: мало пар | `Добавьте минимум 2 пары для сопоставления` |
| Сопоставление: пустой элемент | `Заполните все элементы сопоставления` |
| Сопоставление: нет ключа | `Укажите правильные соответствия` |
| `short_text`, `compact_text_equal`: пустой | `Укажите правильный краткий ответ` |
| `short_text`, `compact_text_in_set`: меньше двух вариантов | `Укажите минимум два допустимых ответа` |
| `short_text`, `compact_text_in_set`: пустой вариант | `Заполните все допустимые ответы` |
| `short_text`, `compact_text_in_set`: повтор после нормализации регистра и пробелов | `Допустимые ответы не должны повторяться` |
| `sequence_digits`: не цифры | `Для последовательности используйте только цифры без пробелов` |
| `validationSchema.minOptions` (N) | `Добавьте минимум {N} {вариант|варианта|вариантов} ответа` |
| `validationSchema.maxOptions` (N) | `Не более {N} {варианта|вариантов} ответа` — склонение: 1 → `варианта`, остальные → `вариантов` (`Не более 1 варианта ответа`, `Не более 5 вариантов ответа`) |
| `validationSchema.exactChoiceCount` (N) | `Отметьте ровно {N} {правильный ответ|правильных ответа|правильных ответов}` |

Правило склонения для `{вариант|варианта|вариантов}` и `{правильный ответ|…}`: последние две цифры 11–14 → третья форма; иначе последняя цифра 1 → первая, 2–4 → вторая, остальное (0, 5–9) → третья. Реализуется чистой функцией в адаптере или в `app/web/lib/` рядом с форматированием (на усмотрение планировщика), с табличным тестом на 1, 2, 5, 11, 12, 21, 22, 25.

Префикс при создании теста с вопросами: `Вопрос {i}: ` + текст сообщения с первой буквой в нижнем регистре (как сейчас: `Вопрос 1: добавьте минимум 2 варианта ответа`). Адаптер возвращает сообщение с заглавной буквы без префикса; вызывающий код добавляет префикс и понижает регистр первой буквы.

`validationSchema.minOptions` по умолчанию ровно 2 (как сейчас); значение типа вопроса, если задано, заменяет 2 в тексте.
