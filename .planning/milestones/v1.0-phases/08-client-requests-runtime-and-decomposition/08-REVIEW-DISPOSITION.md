### Пакет B (08-FIX-B): список попыток

Сервер, `routes/tests/admin/attempts.ts`, `GET /api/tests/admin/attempts`:
- параметры `limit` (1…100, по умолчанию 50), `offset`, `q`, `topic` (slug), `student` (uuid), `from`, `to` (ISO-время, включительно), `status` (`active` | `inactive` | `all`, по умолчанию `all`); неверные значения → 400;
- `q` ищет без учёта регистра по имени ученика, названию теста и темы; без `zone.all` логин в имени и в поиске не участвует (как `studentNameIn`, SEC-06 фазы 07.1);
- ответ: `rows`, `total` (с фильтрами), `limit`, `offset`, `summary` (`passed`, `averageScore` по отфильтрованному набору), `scopeTotal` (всего в зоне без фильтров), `facets` (`topics` [{slug, title}], `students` [{id, name, isActive}] по всей зоне, не по странице);
- зона: `testScope` и `studentAttemptsInScope` как сейчас.

Web, `admin/attempts`:
- SSR — первая страница с умолчаниями (`status=active`); клиент держит фильтры в ключе (строка из `*Keys.*()`), поиск через `use-debounce`, «Показать ещё» догружает следующую страницу по `offset`;
- плитки: «всего в базе» = `scopeTotal`, «показано» = загружено строк из `total`, «пройдено» и средний результат — из `summary`; списки тем и учеников — из `facets`.

Меню (из `deferred-items.md`, найдено в пакете A): `AppSidebar` считает активным каждый пункт из БД, потому что `item.isActive` — флаг видимости. Активен только пункт текущего адреса (`pathname === url` или вложенный путь), «Админка» — на `/admin` и вложенных. Тест чистой функции.

Тесты: серверный — при 105 попытках у одного ученика и 1 старой у другого старый виден фильтром `student` и в `facets.students`; `q`, `topic`, `from`/`to`, `status` фильтруют; учитель не видит чужих тем и не находит ученика по логину. Web — чистая функция построения запроса и склейки страниц.
