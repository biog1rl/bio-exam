<objective>
Типизированный модуль запросов (HTTP-01, D-01 … D-05) и блок ошибки загрузки (D-09, 08-UI-SPEC Поверхности 1 и 2) с трассером на экране диапазона графика.

Purpose: все следующие планы HTTP-02 (08-11 … 08-23) переводят вызывающих на этот модуль. Экран диапазона графика взят трассером из группы 2 D-08: это единственный импортёр `lib/fetcher` и самый маленький экран с чтением и записью.
Tracer — `GET /api/settings/chart-default-range` через `swrFetcher` → `requestJson` → `apiFetch`, отказ сервера → блок ошибки с «Повторить»; сохранение через `request` с `json`.
Output: `lib/http/{request,errors,swr,download}.ts` с тестами, `components/feedback/LoadErrorAlert.tsx`, `lib/settings/api.ts`, переведённый `ChartSettingsPageClient.tsx`.

Решения планировщика (в рамках Discretion CONTEXT):
- `parse(body: unknown): T` бросает `MalformedBodyError` (экспорт модуля) при несовпадении конверта — так проверка может и сузить тип, и преобразовать (D-03).
- Отказ несёт необязательное поле `body` (разобранный JSON не-2xx ответа): без него `AttemptRequestError` фаз 5 и 6 (`code`, `attemptId`) не сохранит контракт в 08-23.
- `requestBlob` при обрыве чтения тела после 2xx отдаёт `network` со `status`: так экспорт отличает тост «Не удалось скачать архив. Попробуйте ещё раз.» от «Нет связи с сервером…» (Поверхность 6).
- `createRequester(fetchImpl)` — шов для тестов без `window`: модуль по умолчанию создан с `apiFetch`.
- Ключ SWR — всегда строка из `*Keys.*()` доменного слоя, `parse` передаётся фетчером `fetcherWith(parse)`, созданным на уровне модуля слоя (C4/R2 ревью): так `mutate('<url>')` у таблиц и диалогов 07.1 попадает в тот же кэш, что и хук экрана. Кортеж `[url, parse]` в ключе запрещён во всей фазе; охранный тест 08-23 запрещает `useSWR([` в `app/web`.
- Для ключа нескольких потребителей (`/api/users`, `/api/tests`, `/api/tests/topics`, `/api/rbac/roles`, `/api/groups`) `parse` только сужает тип и возвращает тело без преобразования, иначе экраны с одним ключом получат кэш разной формы.
- Блок ошибки заменяет содержимое только при `error && data === undefined` (R8 ревью); экран с локальной формой, засеянной из данных SWR, передаёт `revalidateOnFocus: false`.
- Проверка конца центрального каталога ZIP (`hasZipEndOfCentralDirectory`, R9 ревью) живёт в `download.ts`, а не в `requestBlob`: модуль запросов не знает о форматах тел.
