## Phase Boundary

Четыре группы работ, у каждой свой набор планов.

- **Запросы (web и Express).** Один типизированный модуль запросов поверх `apiFetch` из модуля веб-сессии. Он отвечает за 401 (через веб-сессию), ответы с ошибкой, некорректный JSON и сбой сети. Все защищённые вызывающие (16 локальных fetcher'ов, глобальный `lib/fetcher.ts`, голые `fetch` на защищённых экранах) переходят на доменные слои по образцу `lib/tests/api.ts`: пользователи, группы и остальные домены. Express получает поиск пользователя по id и по логину, D7 закрыт. Серверные страницы ходят в Express одним путём (`API_ORIGIN`), самовызов `absoluteUrl` удаляется вместе с доверием к `x-forwarded-host` (SEC-07). Тело ответа в SSR читается на всех ветках (CR-09).
- **Рантайм редактора.** Код редактора не обращается к `document` и `window` при рендере, что доказывает SSR-тест. Ссылка на колбэк в debounce обновляется в эффекте, с отменой при размонтировании. Тулбар подписывается один раз на редактор. Распознавание речи полностью отцепляется при размонтировании. Затронутые анимированные элементы учитывают reduced-motion. React Doctor не находит подтверждённых ошибок из плана 007, production-сборка web проходит.
- **Производительность.** Категории глобального поиска выполняются параллельно, порядок и фильтры прав прежние. Промпты читаются с ограниченной параллельностью в модуле содержимого вопроса. Необязательные группы плагинов редактора и данные эмодзи (324 КБ) грузятся лениво, на чанк редактора есть измеренный бюджет. ZIP экспорта собирается потоком внутри модуля хранилища, с отменой и backpressure, содержимое архива то же. Замеры до и после записаны.
- **Декомпозиция.** Инвентарь маршрутов и характеризационные тесты регистрации и порядка появляются до нарезки. `routes/tests/index.ts` (2737 строк на `aea7e48`) делится на доменные суброутеры, остаётся маленькая точка сборки. Инвентарь до и после совпадает байт в байт.

Требования: HTTP-01 … 04, RT-01 … 04, PERF-01 … 05, DECOMP-01 … 02 (`.planning/REQUIREMENTS.md:119-142`). Источники: `plans/007-frontend-runtime.md`, `plans/008-proven-performance.md`, `plans/010-module-decomposition.md` (шаги 1-2), `plans/011-architecture-deepening.md` §1 D7 и §2 C8, ADR-0001, ADR-0004, ADR-0005. Сюда же перенесено отложенное: из фазы 4 SEC-07 и CR-09 (`04-REVIEW-DISPOSITION.md` → «Отложено»), из фазы 5 `fetchAttemptReview` и `absoluteUrl` на странице разбора, из фазы 6 типизированный слой для `lib/tests/api.ts` и обновление навыков после нарезки, из фазы 7 потоковый ZIP вместо лимита 4,5 МБ (07-14) и ограниченная параллельность чтения промптов.

Видимое поведение меняется:
- администратор открывает из поиска любого пользователя, в том числе за пределами первых 100 (D7); страница `/profile/<login>` находит любого пользователя, а не только из первых 100;
- экраны, которые при ошибке сервера показывали пустой список (`{ error }` разбирался как данные), показывают ошибку загрузки с кнопкой «Повторить»;
- серверные страницы попыток при ошибке Express показывают страницу ошибки вместо пустого списка или 404; при закончившейся сессии ведут на вход;
- у пользователей с системной настройкой «уменьшить движение» затронутые элементы не анимируются;
- редактор вопроса открывается быстрее; кнопки тулбара и результат сохранения те же;
- глобальный поиск отвечает быстрее; категории, их порядок и выдача те же;
- ZIP экспорта: на Vercel лимит 4 400 000 байт и ответ 413 сохраняются, но архив больше не держится в памяти целиком сверх лимита; при снятом лимите (VPS) архив отдаётся потоком без лимита размера.

Что НЕ входит:
- Переезд на VPS, Docker Compose, включение локального адаптера на проде — Milestone 2. Фаза 8 только не мешает ему: лимит ответа задаётся окружением (D-25), сервер и web по-прежнему отдельные процессы.
- Нарезка `routes/tests/public.ts` (DECOMP-02 называет только `index.ts`), разбиение `TestRunner` на хуки (заменено ADR-0005), изменение API, путей и форм ответов, кроме двух новых маршрутов поиска пользователя (D-11).
- Пагинация и поиск в списке пользователей администратора (`UsersClient` показывает первые 100): D7 — это поиск одного пользователя. Пагинация без доказательства кардинальности — вне плана 008.
- Индексы без `EXPLAIN ANALYZE`, изменения формата экспорта и выдачи поиска (scope guard плана 008).
- Права на пункты бокового меню (`sidebar_items`) — Deferred в фазе 07.1, требований в фазе 8 нет.
- Редизайн редактора и замена вендорного кода редактора целиком (STOP плана 007), сырые и косметические находки React Doctor.
- Архив, заранее собранный в объектном хранилище, с подписанной ссылкой и выгрузка через диск — только отчёт при STOP PERF-04 (D-27), не реализация.
- Миграции БД: схема в фазе не меняется.

### Модуль запросов (HTTP-01)
- **D-01 [авто]: один модуль запросов в `app/web/lib/http` (имя файла — Discretion) поверх `apiFetch`.**
  - Две формы на одном ядре:
    - `request<T>(url, options)` возвращает исход `{ ok: true, status, data }` или `{ ok: false, kind, status?, message }` и не бросает;
    - `requestJson<T>(url, options)` бросает `RequestError` с теми же полями.
  - Исходной формой пользуются код жизненного цикла попытки и сохранение черновика (фаза 6), бросающей — SWR и простые вызовы.
  - Виды отказа `kind`:
    - `auth` — сессия закончилась: `apiFetch` уже сделал refresh и повтор, бросил `AuthExpiredError` и повёл на вход;
    - `http` — ответ не 2xx;
    - `malformed` — JSON не разбирается или проверка формы (D-03) не прошла;
    - `network` — `fetch` бросил;
    - `aborted` — запрос отменён `signal`.
  - Параметры:
    - `method`;
    - `json` — тело сериализуется, ставится `Content-Type`;
    - `body` — `FormData` передаётся как есть;
    - `signal`, `keepalive`, `headers`;
    - `parse` — проверка формы.
  - По умолчанию `cache: 'no-store'`, как в `lib/tests/api.ts:16`.
  - Ответ 204 и пустое тело дают `undefined`. Тело ответа всегда прочитано или отброшено.
  - Третья форма — `requestBlob(url, options)` → `{ blob, filename }`: имя из `Content-Disposition`, иначе имя, которое передал вызывающий. Нужна для ZIP (D-26).
- **D-02 [авто]: тексты отказов.** Текст для показа модуль собирает так:
  - `http` с полем `error` в JSON-ответе → текст сервера, как сейчас делают `EditUserDialog.tsx:216-224` и `lib/search/api.ts:11-13`. Исключения:
    - 403 с текстом `Forbidden` или без текста → «Недостаточно прав для этого действия»;
    - прочий `http` без текста → запасной текст вызывающего, если он есть сейчас, иначе «Ошибка сервера (код N)».
  - `network` → «Нет связи с сервером. Проверьте подключение и повторите попытку».
  - `malformed` → «Сервер вернул некорректный ответ. Повторите попытку позже».
  - `auth` → текста нет, тост не показывается: идёт переход на вход. Так сейчас делает `EditUserDialog.tsx:295`.
  - `aborted` → ничего не показывается.
  - Помощник `readApiError` фазы 7 (07-14) становится частью модуля.
- **D-03 [авто]: проверка формы без новых zod-схем на каждый ответ.**
  - Каждая доменная функция передаёт в `parse` узкую проверку конверта, который она читает: `Array.isArray(body.rows)`, `body.user` — объект и т. п. Не прошла → `malformed`.
  - Там, где схема уже объявлена в пакете (`@bio-exam/exam-core`: вид попытки, результат), используется она.
  - Полных схем для каждого ответа пользователей и групп не пишется (альтернатива — в логе).
- **D-04 [авто]: SWR — один fetcher, ключи из доменных слоёв, без глобального провайдера.**
  - Один `swrFetcher` поверх `requestJson`. Доменные хуки (`useUsersList`, `useUserByLogin`, `useGroups` и т. п.) передают его и `parse` явно.
  - Строки ключей строят функции доменного слоя (`usersKeys.list()` = `'/api/users'`). Инвалидация в `EditUserDialog.tsx:237`, `:269`, `ReinviteUserDialog.tsx`, `UsersTable.tsx` идёт через них, сами строки не меняются.
  - Удаляются `lib/fetcher.ts` (`fetcher`, `swrOptions`) и `lib/swr-config.ts` (`swrConfig`). `SWRConfig`-провайдера в приложении нет, `swrOptions` и `swrConfig` никто не импортирует, поэтому сейчас действуют настройки SWR по умолчанию. Они и остаются: удаление ничего не меняет.
- **D-05 [авто]: `apiFetch` уходит внутрь.**
  - `apiFetch` импортируют только `lib/session/*` и модуль запросов. Реэкспорт `lib/api-fetch.ts` удаляется или остаётся только для модуля (Discretion).
  - `AuthExpiredError` вызывающие получают из модуля запросов.
  - Загрузки (`components/ui/image-upload.tsx:146`, `:190`, медиатека) идут через модуль с `FormData`.
  - Поиск (`lib/search/api.ts`) передаёт `signal`: новый ввод отменяет прежний запрос.
