# Phase 5 — UI Design Contract

> Узкий контракт на три поверхности, которые фаза меняет в видимом тексте и поведении: ошибки старта и отправки в `TestRunner` (403, 409, 422, 404, сбой, нет сессии, возврат к просроченной попытке), карточка результата вопроса при 0 баллов, разбор администратора для старой попытки без ключа на момент сдачи. Режим автономный, вопросов пользователю не задавалось. Решения выбраны по существующей вёрстке `TestRunner.tsx` и `attempt-review/*` и по решениям D-01…D-25 из `05-CONTEXT.md`; где спека потребовала бы ответа пользователя, стоит пометка **[авто] требует подтверждения**. ## Поверхность 1. `TestRunner`: ошибки старта и отправки (D-01, D-03, D-05, D-09, D-11)

Файлы: `app/web/components/tests/TestRunner.tsx`, `app/web/lib/tests/api.ts`. Вёрстка страницы, таймер, навигация, кнопки `Назад`, `Далее`, `Завершить`, оверлей автосдачи «Время вышло / Отправка ответов...», диалоги «Начать тест?» и «Есть неотвеченные вопросы» не меняются.

Фокус экрана: при ошибке отправки взгляд идёт к одному элементу — модальному диалогу (409, 422) или к плашке ошибки над вопросом (остальные случаи). Одновременно на экране не бывает и диалога, и плашки, кроме случая «диалог 409 закрыт» (тогда остаётся только плашка).

### Как web различает ответы

`fetchJson` сейчас бросает `Error(text)` без статуса. Для отправки и старта `api.ts` бросает ошибку, в которой есть HTTP-статус и разобранное поле `error` тела (и `attemptId` для 409). `TestRunner` выбирает реакцию так:
- 409 и 422 — по коду в `error` (`ATTEMPT_ALREADY_SUBMITTED`, `TIME_EXPIRED`); 409 с другим кодом обрабатывается как сбой;
- 403, 404, 400, 5xx — по HTTP-статусу; текст сервера `Тест не назначен` и английские строки (`Test not found`, `Bad request`) на экран не выводятся;
- 401 — по контракту фазы 4 (модуль веб-сессии), фаза 5 его не меняет.

Серверу код для 403 не добавляется: тело `{ error: 'Тест не назначен' }` остаётся как в D-01. **[авто] требует подтверждения** (альтернатива — машинный код в теле 403; это меняет API для всех клиентов).

### Плашка ошибки

Существующий блок `submitError` остаётся единственной плашкой ошибки старта и отправки, место то же (под блоком «Результат», над вопросом):

```tsx
<section className="flex flex-wrap items-center justify-between gap-4 rounded-lg border border-rose-200 bg-rose-50 p-4">
	<span role="alert" className="text-sm">{message}</span>
	{action ? (
		<Button variant="outline" size="sm" onClick={action.onClick}>
			{action.label}
		</Button>
	) : null}
</section>
```

Отличия от текущей разметки: `role="alert"` у текста (кнопка вне live-области и не озвучивается вместе с сообщением), `flex-wrap` (на ширине 375px кнопка уходит под текст, а не сжимает его) и `text-sm` у текста (сейчас текст наследует 16px). Кнопка есть только там, где она в таблице «Тексты». `Обновить страницу` вызывает `window.location.reload()`.

Проверка «по часам клиента» нужна, чтобы возврат к просроченной попытке не открывал новую сессию с таймером до того, как студент нажал `Начать заново`. Льгота 2 минуты совпадает с `GRACE_PERIOD_MINUTES` на сервере; при расхождении часов срабатывает строка «другой `sessionId`». **[авто] требует подтверждения** (альтернатива — всегда вызывать `/start`, тогда новая попытка с таймером начинается без подтверждения, а студент видит только тост).

`Пройти ещё раз` в блоке «Результат» и `Начать заново` в диалоге 422 — одно действие; второго подтверждения нет, диалог 422 сам служит подтверждением сброса ответов.

### Разметка пометки

После `QuestionAnswerReview` и перед строкой телеметрии:

```tsx
<p role="note" className="mt-4 flex items-start gap-2 rounded-2xl border border-dashed border-border/70 bg-secondary/45 px-4 py-3 text-sm text-muted-foreground">
	<KeyRound className="mt-0.5 size-4 shrink-0" aria-hidden="true" />
	<span>{text}</span>
</p>
```

`mt-0.5` у пиктограммы выравнивает её по первой строке текста (исключение 2px, как у строки баллов в `TestRunner`). Пунктирная рамка отличает пометку от карточек ответа со сплошной рамкой. На узкой ширине текст переносится, пиктограмма остаётся у первой строки.

Студенту эти состояния не показываются: студент видит только вид только что сданной попытки (версия 2), отдельной страницы разбора для студента нет (D-15).

## UI Considerations

Доступность: текст плашки ошибки получает `role="alert"` (сейчас live-области нет, кнопка в неё не входит) и озвучивается один раз при появлении. `Dialog` 409 и `AlertDialog` 422 — Radix: фокус уходит в диалог при открытии и ловится внутри; у 422 единственная кнопка `Начать заново` получает фокус, `Esc` диалог не закрывает (как у «Начать тест?»).
