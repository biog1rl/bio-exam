# Project Retrospective

*A living document updated after each milestone. Lessons feed forward into future planning.*

## Milestone: v1.0 — Надёжная основа

**Shipped:** 2026-10-06
**Phases:** 9 (1–8, 07.1) | **Plans:** 140 | **Tasks:** 222

### What Was Built
- Одна проверка `yarn verify`, CI на GitHub и изолированный e2e на компьютере и телефоне (236 сценариев).
- Модули по ADR-0001…0005: exam-core, вход и сеансы в Express, сохранённая попытка, жизненный цикл попытки на клиенте, хранилище с двумя адаптерами и модуль содержимого вопросов, слой запросов web.
- Роль учителя с зонами ответственности (вставленная фаза 07.1 по запросу клиента).
- Дефекты D1–D8 закрыты; ускорения подтверждены замерами до и после.

### What Worked
- Характеризационные тесты перед каждой переделкой модуля: регрессии ловились до выкатки.
- Отряды ревью (код, безопасность, тесты) с последующим devils-advocate: из заявленных MAJOR подтверждались только реальные, правки шли пакетами.
- Исполнение фаз в отдельном worktree с коммитом на план и перебазированием на dev перед слиянием.
- Хотфиксы с прода (аватар, вход, поиск, base64-картинки) шли напрямую в dev и не ждали фазы.

### What Was Inefficient
- Ручные проверки фаз 2–7.1 копились в «ждёт человека» до переезда; закрывались пачкой.
- Отпечатки VERIFICATION устаревали при каждой следующей фазе; пересчёт без повторного верификатора.
- Юнит-тесты web раздувались повторами одной обработки ошибок по доменным слоям; уборка 1470 → 1208.
- Нестабильные e2e под нагрузкой (клик до гидратации, тост поверх кнопки) находились только полным прогоном.

### Patterns Established
- Доступ к объектам только через `services/access-policy`; ветвление «админ или учитель» через зону.
- Новые проверки — серверные интеграционные (настоящая БД) и e2e; юнит-тесты — для логики с вариантами; без хрупких структурных охранников.
- Серверные шаги выкатки — блоками `( set -Eeuo pipefail … )` с итоговой строкой, по одному.

### Key Lessons
1. Данные прода дают проблемы, которых нет в сидах: base64-картинки в вопросах нашлись только по жалобе на скорость.
2. Списки в интерфейсе с фильтрами в браузере ломаются на объёме: фильтры и постраничная выдача — на сервере сразу.
3. Ручные проверки закрывать сразу после выкатки фазы, а не копить.

### Cost Observations
- Model mix: исполнители и критики — opus, структурные проверки и сверки — sonnet.
- Notable: параллельный разбор покрытия по фазам (8 исполнителей) занял минуты вместо прохода в одном контексте.
