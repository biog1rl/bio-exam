# MVP открытых вопросов: контракт срезов (2026-10-16)

Срок: выкатка через неделю. Решение владельца записано в память проекта `mvp-open-questions-a-week`. GSD не используется: ни планов, ни отрядов, ни ревью-фаз. Ведущая сессия (Bioexam main) раздаёт срезы, потом проверяет их и гоняет `yarn verify`.

## Охват MVP

Входит: открытый вопрос создаёт автор; ученик отвечает текстом и фото; сдача даёт «на проверке»; окно загрузки фото и «Готово, фото загружены»; очередь и экран проверки у учителя/админа (оценка 0–3, комментарий); пустой ответ после закрытия окна получает автоматический 0 «нет ответа»; итог и уведомление ученику; тип `open` включается авторам.

Не входит (не делать, не заводить, не готовить заготовок): QR и страница на телефоне без входа, возврат на доработку, версии ответа, история проверок, повторная оценка, уведомления учителю, зум и поворот фото, срок хранения, каталог типов вопросов, миграции Supabase/Vercel. Фото с телефона ученик грузит со своего аккаунта обычным окном загрузки.

## Правила для всех срезов

- Не коммитить. Не запускать `yarn verify` и `yarn e2e` (их гоняет ведущая сессия). Гонять только typecheck, lint и точечные тесты своего пакета: `yarn workspace @bio-exam/server typecheck`, `yarn workspace @bio-exam/web typecheck`, тесты с БД только через `node scripts/with-test-db.mjs yarn workspace @bio-exam/server test <файл>`.
- Не писать комментарии в коде. Тексты интерфейса на русском. Тесты по `test-hygiene`: только логика с вариантами и правила доступа, без хрупких охранников.
- Перед правкой области прочитать навык из `.agents/skills/<имя>/SKILL.md` (`bio-exam-web`, `bio-exam-api`, `bio-exam-data`) и `AGENTS.md`.
- Применённые миграции не править. Миграция 0032 только у среза S3. Новая переменная окружения только вместе с `.env.example`.
- Чужие незакоммиченные файлы не трогать: `app/web/app/(internal)/(protected)/admin/tests/components/bank/BankExplorer.tsx`, `e2e/tests/bank.spec.ts`, `e2e/tests/teacher-zone.spec.ts`.
- Менять только файлы своего среза. Общие файлы (`packages/exam-core/src/index.ts`, `app/server/src/routes/tests/index.ts` и подобные) править точечной строкой, перечитав файл перед правкой.
- Готовый предикат очереди лежит в `app/server/src/services/scored-attempt/review-ready.ts` (`reviewReady`, `REVIEW_READY_SQL`): ответ попадает в очередь и может быть оценён, когда окно загрузки закрыто или не задано. Править его нельзя, только использовать.
- Отчёт в конце: список изменённых файлов, что проверено командами (с итогом), что не проверено.

## Данные и решения

- Ответ на открытый вопрос: текст в `answers[questionId]` (строка, как у остальных, автосохранение уже работает), фото в `answer_photos` (сессия + вопрос, фаза 12).
- Эталонный ответ и критерии: поле «пояснение» вопроса (`explanationText`, файл `explanation.md`). Для типа `open` оно называется «Эталонный ответ и критерии». Видят автор и проверяющий; ученик видит после итога попытки, как обычное пояснение (так уже работает разбор). Нового столбца и файла не заводим.
- Оценка: целое 0–3 за вопрос (`OPEN_QUESTION_MAX_POINTS = 3`), комментарий необязателен. Итог попытки считает `materializeAttemptOutcome` с `latestScores` (карта questionId → оценка).
- Пустой ответ: ученик не может сдать, если у открытого вопроса пустой текст и 0 фото (422, код `OPEN_ANSWER_EMPTY`). Сдача по дедлайну (`submitSource = 'deadline'`) разрешена с пустым ответом. Когда окно закрылось, а у открытого вопроса по-прежнему нет текста и фото, он получает оценку 0 с комментарием «нет ответа», без проверяющего (`reviewer_id` NULL), и в очередь не попадает.
- Ссылки между срезами:
  - `POST /api/tests/public/tests/:id/sessions/:sessionId/uploads-done`: ученик завершает окно досрочно (S2). Только владелец сессии, идемпотентно: ставит `test_attempts.upload_closes_at = now()` для попытки этой сессии, если окно ещё открыто. Ответ 200 `{ uploadClosesAt: string }`. Отказы окна: те же коды и тело, что у загрузки фото.
  - Проверка (S3): `POST /api/tests/admin/attempts/:attemptId/questions/:questionId/review`, тело `{ score: 0|1|2|3, comment?: string }`, ответ 200 `{ review: { questionId, score, comment, reviewedAt, reviewerName }, attempt: { reviewStatus, finalScorePercentage, finalPassed } }`. Правила: `canReviewAttempt` (зона учителя или админ), нельзя оценивать свою попытку (403), нельзя до `reviewReady` (409 `REVIEW_NOT_READY`), вопрос должен быть открытым вопросом этой попытки (404 иначе). Повторная оценка того же вопроса перезаписывает оценку (новая строка в `answer_reviews`, последняя побеждает); окончательная проверка версии не нужна.
  - Чтение для проверки (S3): `GET /api/tests/admin/attempts/:attemptId` (уже есть) дополняется для открытых вопросов полем `open: { text: string, photos: Array<{ id: string; uploadedAt: string }>, review: { score, comment, reviewedAt, reviewerName } | null, referenceText: string | null }`. Файл фото берётся через существующий `GET /api/answer-photos/:photoId/:variant` (`full` или `thumb`). Ученику в его результате: `review: { score, comment } | null` на том же вопросе, `referenceText` только после итога попытки.
  - Очередь (S2): существующий список `GET /api/tests/admin/attempts?review=pending` и счётчик `pendingTotal` на дашборде показывают только попытки с `reviewReady`.

## Срезы

### S1. Web: редактор, ввод ответа, фото после сдачи (сессия phase-13-prep, Sonnet)

Файлы: `app/web/app/(internal)/(protected)/admin/tests/**` (редактор и его типы/сохранение), `app/web/components/tests/QuestionInput.tsx`, `app/web/components/tests/TestRunner.tsx` и то, что оно использует в `components/tests/**`, кроме `attempt-review/**` (его ведёт S4 после S3).

1. Редактор вопроса: для шаблона `open` скрыть поле «Правильный ответ», показать панель «Эталонный ответ и критерии» на `Editor` (MDX), привязанную к `explanationText`; проверить, что `explanationText` уходит в сохранение и черновик вопроса и возвращается при открытии (если нет, довести до сохранения). Подсказка в панели: ученик увидит текст после проверки. Тип «Открытый вопрос» в списке типов уже есть (неактивный): он появится у автора после включения (S5), для проверки заводить через сид e2e.
2. `QuestionInput`: для `open` многострочное поле (Textarea из `components/ui`), счётчик «N из M знаков» (лимит из `exam-core`, найти константу длины открытого ответа), автосохранение через существующий `onInputTextAnswer`, режим только чтения после дедлайна как у остальных.
3. Раннер: блок фото уже стоит под полем (`PhotoBlock`), оставить; на телефоне кнопки «Сделать фото» и «Выбрать из галереи» должны работать (проверить `capture`/`accept` в `SourceInput`).
4. Экран после сдачи: у открытого вопроса со статусом «на проверке» показать, до какого времени можно добавлять фото (`uploadClosesAt`, `uploadWindowView`), блок фото (добавить/удалить, пока окно открыто) и кнопку «Готово, фото загружены» (вызов `uploads-done` из контракта, после ответа блок закрывается). Если окна нет, показать «На проверке».
5. Быстрые проверки в браузере (`preview_start`, сид e2e с активным `open`), результат в отчёт.

### S2. Server: сдача, окно, очередь

Файлы: `app/server/src/services/attempt-sessions/**`, `app/server/src/routes/tests/public.ts`, `app/server/src/routes/tests/admin/attempts.ts`, `app/server/src/services/answer-photos/**` (только привязка к попытке), `app/server/src/schemas/**` и `packages/exam-core/src/attempt-session.ts` (коды ошибок), тесты рядом.

1. `OPEN_ANSWER_EMPTY` при сдаче (правило выше), тело ответа 422 `{ error: 'OPEN_ANSWER_EMPTY', questionIds: string[] }`, код добавить в `exam-core` рядом с остальными кодами сдачи; web-клиент (S1 не трогает, S2 тоже) покажет общий текст отказа через существующую обработку 422, проверить, что ответ с неизвестным кодом не ломает клиент.
2. Привязка `answer_photos.attempt_id` в транзакции сдачи (проверить, есть ли; если нет, добавить).
3. `uploads-done` по контракту, тесты: владелец, чужой, уже закрыто, идемпотентность.
4. Очередь: `review=pending` в списке попыток и `pendingTotal`/плитка дашборда считают только `reviewReady`; в ответе попытки у staff отдаётся `reviewReady: boolean`.

### S3. Server: проверка

Файлы: новая миграция `app/server/drizzle/0032_answer_reviews.sql` (+ `meta`, `migrations-manifest.json`, `schema.ts`), `app/server/src/services/answer-reviews/**` (новая папка), `app/server/src/routes/tests/admin/reviews.ts` (новый), чтение для проверки в `app/server/src/services/scored-attempt/**` (кроме `review-ready.ts`), фоновая задача рядом с `app/server/src/services/background-jobs/**`, уведомление в `app/server/src/services/notifications/**`, `packages/exam-core/src/review.ts` (новый) и строка экспорта в `packages/exam-core/src/index.ts`. Прочитать `docs/adr/0007-user-deletion-rule.md` и навык `bio-exam-data` до миграции.

1. Таблица `answer_reviews`: `id`, `attempt_id` (каскад от попытки), `question_id` (каскад от вопроса), `score smallint` (CHECK 0..3), `comment text` (до 2000 знаков), `reviewer_id uuid` NULL (при удалении проверяющего — SET NULL, по ADR-0007), `created_at`; RLS как у соседей. Индекс `(attempt_id, question_id, created_at)`. Тест каталога внешних ключей из ADR-0007 должен проходить.
2. Служба: сохранить оценку в транзакции (блокировка попытки `FOR UPDATE`), собрать `latestScores` (последняя строка на вопрос), вызвать `materializeAttemptOutcome`; при `reviewStatus` `graded` записать уведомление ученику (событие вида «работа проверена» в той же транзакции через `recordNotifications`, ссылка на результат попытки). Подключить `loadLatestScores` в `reconcile-outcomes` (сейчас `new Map()` в `background-jobs/jobs.ts`).
3. Маршрут и чтение по контракту. Права: только `canReviewAttempt`, самопроверка запрещена.
4. Авто-0: фоновая задача (рядом с `finalize-deadlines`): для попыток `pending` с закрытым окном, где у открытого вопроса нет текста и фото, добавить оценку 0, комментарий «нет ответа», `reviewer_id` NULL, пересчитать итог. Запускается и при ручном `jobs:run`.
5. Ученику: на результате попытки у открытого вопроса оценка и комментарий; `referenceText` только после `graded`.
6. Тесты: права (чужая зона, своя попытка, до окна), итог после последней оценки, авто-0, идемпотентность задачи.

### S4. Web: экран проверки (после S3)

Файлы: `app/web/components/tests/attempt-review/**`, страница попытки у staff, ссылки очереди. Читает контракт выше. Экран: для открытого вопроса текст ответа, фото (миниатюры и открытие `full` в новой вкладке или модальном окне, без зума), метка времени загрузки и «после окончания времени», эталон и критерии, форма «Оценка 0–3 + комментарий + Сохранить», состояние «Оценено: N» с возможностью исправить. Очередь: фильтр «Ждут проверки» уже есть в списке попыток, плитка дашборда ведёт туда. Ученику: оценка и комментарий в разборе.

### S5. Включение (ведущая сессия)

e2e петли, `yarn verify`, включение типа `open` (миграция данных или переключатель в админке типов), шаги владельца: проверка на телефоне, выкатка 0031 + 0032 вручную через `deploy.sh`.
